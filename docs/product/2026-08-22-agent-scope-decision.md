# 智能体范围决策：不训练，完成报价内语义 RAG 闭环

日期：2026-08-22  
状态：作者已确认

## 决策

训练、微调、租用 GPU、训练数据集和独立 LLMOps 平台不在报价范围，本项目不实施。
不因单次模型横评改变生产模型，也不整体引入新的通用 Agent 框架。

下一步只完成报价表中的“规则引擎 + 知识库智能体”：

1. 规则引擎继续确定证型、分期与方案，模型不得改判；
2. 把当前字面 `LIKE` 检索替换为语义检索，并保留来源；
3. 模型可按自然问题调用受限的只读知识搜索工具，不建立关键词或成人、儿童、患者、公益
   团队路由；所有后台已启用知识进入同一检索集合，分类只用于运营管理，不增加
   患者问答/专业参考等用途分类或第二套知识库；
4. 每轮只注入相关知识、规则结果、当前方案和必要会话事实；
5. 模型负责追问、解释和通俗转译；不检索路径保持一次生成调用，需要知识时只允许一次
   搜索工具往返，不增加独立审阅模型；
6. 服务端只校验证型、方案、穴位、方法、次数、时长、力度等硬事实，不做全文关键词路由，
   不增加串行第二模型审批；
7. 无足够知识时自然说明依据不足并追问，不用生硬模板，也不借模型常识补医学动作。

这里的“已启用”只是知识生命周期状态，不表示新增了一层医学审批。检索结果只
提供相关证据，不改变规则引擎，也不自动变成个体化方案或新的医学动作。

## 首个开发切片的验收线

- 既有 10 条同义检索集 Hit@3 不低于 9/10；
- truth 授权题保持 5/5；
- 一般鼻健康知识问法能基于已启用知识自然回答并保留来源；
- 无依据的穴位、药量、次数、时长和力度不出现在患者可见输出；
- 不新增受众路由、训练依赖、第二模型审阅或新运行时框架；
- 相关窄测和 `cd src && npm run check` 通过，外部资源缺失造成的跳过如实报告。
