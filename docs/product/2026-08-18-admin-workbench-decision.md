# 客户决策：报价内管理后台工作台与推送口径

- 状态：已确认，进入实施
- 创建日期：2026-08-18
- 关联状态板条目：`state/board.md` 第 101 轮
- 关联调研：[005 · 报价内可运营管理后台与首项工作取舍](../research/005_admin-operable-backoffice/decision.md)

## 背景

现有管理后台的文章、视频、站内消息和知识库服务端能力已经存在，但 Web 端主要是单页 section 切换、统计首页和内嵌表单，运营人员不容易定位待处理任务、理解状态或恢复异常。

## 必须决策的原因

后台范围必须与报价单一致；“推送”若被解释为微信订阅通知，会新增微信授权、配置、失败路径和交付范围。Agent 不应替作者扩大功能，也不能把视觉改造冒充新的业务能力。

## 选项

### A．在现有后台上改造成任务型运营工作台（推荐，已选）

- 做法：保留 Vite/React、既有管理命令、会话、确认、版本和审计；工作台先显示待办，文章、视频、知识库列表增加搜索、状态筛选、下一步和结果回读。
- 对范围、成本、工期和体验的影响：不换技术栈、不新增数据库域；首轮集中解决报价三条管理链的可运营性，降低回归风险。

### B．只做视觉换肤或另起一套后台

- 做法：继续保留原单页操作结构，或迁移到通用 Next/Neon 后台模板。
- 对范围、成本、工期和体验的影响：可能短期更换外观，但不能解决任务定位、状态反馈和错误恢复，还会扩大实现和回归成本。

## 已确认的报价范围

- 文章：新增、编辑、校验、上架、下架，并通过应用内站内消息向登录用户推送。
- 视频：上传、编辑、校验、上架、下架。
- 知识库：上传、更新、分类、删除、索引、启用、停用和检索测试。
- 不加入：微信订阅通知、用户运营、模型中心、临床规则编辑、复杂 RBAC、BI 看板。
