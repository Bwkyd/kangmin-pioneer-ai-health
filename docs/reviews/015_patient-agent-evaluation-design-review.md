# 患者智能体评测体系设计三视角复核

评审对象：`docs/plan/012_patient-agent-evaluation-system.md`

基线：`main@c9b4e4b`，设计未提交、未实现

## 患者视角

- 初稿 P2：50 题分布没有明确多轮数量，可能只测单问单答却声称覆盖对话式智能体；已要求旧功能
  回归至少 3 题为多轮，并加入特殊人群、否定式和意图反转变式。
- 复核后未发现 P0/P1/P2。五维 rubric 同时检查直接性、可懂性与安全有用，能识别“带来源但
  没回答所问”和“为了安全什么都拒绝”两类患者体验失败。

## 工程视角

- 初稿 P1：任务把唯一知识文件作为硬期待，会重现迎香精确旧知识压过手册总表却被误判失败的
  打分器错误；已改为可接受证据集合，逐章召回只作独立覆盖诊断。
- 初稿 P1：提供方错误只单列而不计能力失败，可能在真实超时下仍通过发布门；已明确根因单列、
  端到端 pass 和门禁仍判失败。
- 初稿 P2：当前端口不返回模型原文、token 和完整检索轨迹，计划却默认可记录；已在实施顺序中
  增加只服务合成题的可观察端口，不复用生产日志或改变患者合同。
- 复核后未发现 P0/P1/P2。L0–L3 分层、环境指纹和隔离试次符合当前单仓脚本起步的现实。

## 医学安全视角

- 初稿 P2：LLM 裁判只有总体一致率，仍可能稳定误放少数高风险答案；已增加校准集中 P0/P1
  错误答案误放为 0 的条件，且医学事实仍由 truth、规则或明确来源提供。
- 复核后未发现 P0/P1/P2。概念—操作正负配对、24/24 专业操作不泄漏和 P0/P1 不允许平均分
  抵消，能同时防危险放行与无差别拒答。
