# 010 · 管理后台内容录入对抗性评审

> 状态：已完成；日期：2026-08-18；基线：`main@bf8038d`；方法：`km-review`，五个互异单一视角；对象：作者提供的文章新增页截图，以及当前 `src/` 管理端、服务端发布链和患者端投影。

## 结论

本轮未发现需要立即停机或阻断所有管理端操作的 P0；发现 8 项 P1，均应在继续交付内容运营后台前修复或由作者明确收窄能力边界。作者指出的“不能直接添加文件”和“视频为什么出现通用文件类型”成立，但根因不是服务端不支持上传，而是上传上下文与内容编辑表单被拆开，界面没有把两者连接起来。

本轮只评审和记录，不修改 `src/`、不改变 truth、医学规则、数据库或部署；`hi.md` 未修改、未跟踪。

## 分身结果

### 内容运营操作者视角

- 新增文章时只能在“封面素材”下拉框引用既有素材；上传入口在侧栏“素材库”，表单没有“上传并作为封面使用”或返回后保留草稿的路径。
- “保存草稿”表单却把标题、分类、摘要、正文、来源全部设为浏览器必填；同时页面把下一步描述为“编辑、校验、发布”。运营人员无法先保存半成品，切换侧栏或取消还会丢失当前长正文。
- 首次进入空库时，文章封面只能看到“不设置”，视频文件只能看到“请选择已上传视频”，没有告诉操作者下一步应先去哪里上传。

### 媒体素材管理员视角

- 素材库是通用上传器，文件选择器没有 `accept`，服务端允许图片、视频、Word、PDF、Markdown；但媒体卡片只显示 `I/V/W/P/M` 首字母和原始 `ready` 状态，没有中文类型、缩略图、用途、时长或“用于当前字段”的动作。
- 视频表单只从 `readyMedia.filter(item.kind === "video")` 中提供下拉选项；上传了 Word/PDF 或上传中的视频后，操作者会以为“上传成功但视频列表没有”，界面没有解释这种过滤关系。
- 文章正文是纯文本 `<textarea>`，当前内容模型只提供一个封面媒体 ID，没有正文图片、文件导入或结构化内容块入口；通用素材库并不能解决正文内插图。

### 患者端可懂性视角

- 管理端“校验”只调用发布校验并弹出“校验通过，可以发布”，没有在发布前展示患者端实际文章/视频详情；设计文档要求的患者端效果预览没有落到当前 Web 表单。
- 患者端当前把正文作为单个文本块展示，管理员无法在发布前确认换行、封面、视频海报、来源和免责声明的最终组合效果。

### 工程事实视角

- `createCategory()` 忽略 `run()` 返回的成功标志；分类创建失败后仍把失败的分类名写入草稿并清空输入，之后保存会落入“分类不存在/下拉无选项”的死路。
- 管理端表单的“保存草稿”约束比服务端草稿创建契约更严格：服务端创建时仅标题通过 `requiredString`，其余字段可先为空；发布时才检查摘要、正文、来源和视频文件。前后端状态语义不一致，导致草稿阶段无法发挥作用。

### 医学安全视角

- 视频表单允许填写“操作提示”和“注意事项”，但患者端 `PublicContent` 契约、读取 SQL 和文章/视频详情渲染都没有这两个字段；发布后这些字段不会到达患者端。若运营人员把安全边界写在这两个字段里，后台会显示已保存，患者却看不到。
- 当前固定免责声明仍由患者端读取层提供，因此没有证据证明本轮存在立即停机级 P0；但视频安全字段的“后台可填、患者不可见”属于交付前必须阻断的 P1。

## P0 与边界

- P0：未发现。当前证据没有显示认证绕过、患者数据泄露、发布状态越权或已造成不可逆数据破坏；P1-07 仍必须在继续交付视频运营前关闭。
- 共享素材库支持 Word/PDF/Markdown 本身符合现有管理端素材/知识范围；问题是视频/封面上下文没有把可用类型和后续用途表达清楚。
- 本轮未把“是否必须封面”“文章是否必须富文本”“视频安全字段是否必填”擅自写成医学或产品 truth；这些需要作者确认后再固化为发布门禁。
