## 三视角复核

### 患者可懂性

- 当前未配置网络时，问助手显示“问助手暂未开放”，学一学显示不可用提示，健康记录明确标注为本地体验；这条降级边界是可理解的，不能把它计为报价功能已交付。
- 首页仍展示“诊一诊”“学一学”和“科普文章与视频”等入口，入口存在不等于内容可用；正式验收必须从患者入口走到真实结果、内容详情和消息已读。
- 文章、视频、消息的空态不能拿来替代内容供给；至少需要一份已审核文章、一份已审核视频和一条应用内通知作为验收数据，内容事实由负责人确认。

### 工程事实

- `src/apps/kangmin-miniprogram/src/config.js:7-15` 当前关闭网络与微信登录，只打开本地健康记录。
- `src/apps/kangmin-miniprogram/src/utils/request.js:141-157` 在本地体验不支持的命令上会因网络不可用而 fail-closed；`wx.login → /v1/auth/wechat → Bearer` 路径已有实现，但本轮未以真实微信身份验证。
- `src/apps/kangmin-miniprogram/src/utils/local-experience.js:1-3,127-180,254-255` 分别说明本地健康数据会丢失、支持本地症状/日历/趋势、消息本地固定为空。
- 正式服务匿名只读核验：`/live` 正常；视频列表可返回已发布记录，文章列表当前为空。该结果支持“服务端已有部分内容能力”，不支持“患者小程序在线内容已验收”。
- 已执行并通过：`bash scripts/check-tools.sh`、`npm run check --workspace @kangmin/miniprogram`、`npm run test:smoke:miniprogram`（4/4）、`npm run test:smoke:record`（3/3）、`npm run test:smoke:shell`（6/6）、`npm run test:smoke:core`（2/2）、`npm run test:smoke:content`（2/2）和 `git diff --check`。这些结果只覆盖源码、服务冒烟、本地体验或 mock，不扩大为微信真机、客户验收或生产就绪。

### 医学安全

- 当前安全降级是正确边界：没有合法域名、身份或服务异常时不伪造患者结果、不返回假记录、不把模型回答提升为证型、期别或方案。
- 正式联调时仍须让固定规则负责问卷顺序、期别、证型和方案，模型只做受控解释、知识问答和通俗转译；未知、关键临床信息不足、规则冲突和协议异常必须继续 fail-closed。
- 本轮不修改问卷、证型、期别、调理方案、操作参数、禁忌或 truth；#386 的助手验收条件已把这些安全边界列为关闭门槛。

- P1：4。#385–#388 均是报价范围未完成或无法实效验收的交付阻塞项，已全部提交。
