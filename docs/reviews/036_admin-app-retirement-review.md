# 管理后台独立与患者 Web 退役交付评审

- 基线：`codex/src-fractal-02`，源自 `origin/main@628b55f`
- 对象：`src/apps/kangmin-admin/`、旧 `src/web/` 退役、HTTP 静态入口与测试迁移
- 方法：sequential-thinking 元反思；`km-review` 患者可懂性、工程事实、医学安全三视角

## 患者可懂性视角

- P0–P2：未发现。
- 患者端唯一界面已明确为微信小程序；本轮未改变患者文案、问卷、诊断边界或服务端返回。小程序 28 条相关逻辑测试与完整患者服务测试保持通过。
- 微信开发者工具和真机不在本地自动化范围内，不能把当前证据扩大为真机验收。

## 工程事实视角

- P1（已修）：初版把“删除患者 Web”错误扩张为让既有 `/admin` 返回 404，会破坏线上书签、探测与运维入口。修复后 `/` 与 `/admin` 都读取唯一 `dist/web/index.html`，结构收敛但兼容网址不断；HTTP 窄测与真实 Chromium 均覆盖两条路径。
- P2（已修）：第一次完整门禁发现 `http.e2e` 仍断言旧患者 DOM `id="root"`。已改为后台根节点，并保留该测试真正验证的开发预览会话恢复与客户端隔离，第二次完整门禁通过。
- 最终 P0–P2：0。后台包独立 build/typecheck/test；真实浏览器以真实 SQLite、HTTP 和 HttpOnly Cookie 完成登录、文章保存发布、三类模块导航与双视口检查。完整根门禁 438 项中 360 通过、78 项因本地未配置 PostgreSQL/S3 跳过、0 失败。

## 医学安全视角

- P0–P2：未发现。
- 本轮不改确定性问卷、证型、分期、方案匹配、知识发布门禁、数据库内容或模型调用；删除的是旧显示壳，患者能力仍由同一应用服务和小程序调用。

## 结论

P0、P1、P2 已清零，可以进入 PR/CI。演化指标必须按两条线解释：代码文件 319→306、超 600 行绝对数 45→44，但占比因分母缩小为 14.4%；导航成本小降至 13.61、用例密度升至 6.3，不能宣称整体复杂度问题已经解决。

P3：旧混合浏览器脚本曾覆盖大量患者 Web 专属交互；退役后没有机械保留无效 DOM 测试。若运营端上传、知识维护或视频发布发生真实 UI 回归，应按独立行为轴补充小型后台 E2E，而不是恢复一个跨患者端与后台的超长顺序脚本。
