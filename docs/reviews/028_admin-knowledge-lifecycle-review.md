# 管理后台知识生命周期元反思与交付前复核

> 日期：2026-08-26
> 基线：`main@5264455` 加 `codex/issue-276-knowledge-lifecycle` 当前实现。
> 对象：知识上传、原子换文件、单资料测试、明确启用、列表分页和回归证据。

## 患者可懂性视角

本轮管理界面把上传、索引、测试和启用收进一个连续任务，每个状态只突出一个下一步；换文件
明确提示会先停止参与问答。患者端没有增加入口或暴露检索、分块、素材 ID 等内部状态。未发现
P0–P2 问题。

## 工程事实视角

首轮发现一项 P1：全库复核与单资料任务共用查询命中状态，先完成全库命中后新增或换文件，
旧命中可能错误解锁“明确启用”。现已在新增与换文件进入工作流的边界同时清空查询和命中，
真实浏览器分别制造旧全库命中后验证启用仍禁用，完成当前资料测试后才解锁。

仓储替换在 SQLite/PostgreSQL 事务中按“锁定与版本比较 → 素材 ready 复核 → CAS 更新 → 删除
旧向量/分块 → 插入新分块”执行；异常整体回滚。服务窄测覆盖启用状态重置、解析失败安全停用、
素材缺失保持旧患者命中，PG 契约覆盖旧向量删除和陈旧版本拒绝。真实浏览器覆盖 25 条分页、
上传失败同文件重试和完整生命周期；修复后未发现 P0–P2 问题。

## 医学安全视角

本轮不修改问卷、证型、分期、方案、穴位、疗法或临床 truth。患者检索仍只读取 `enabled`；
单资料测试只能由管理命令按明确知识 ID 调用，不能提升为患者全库规则。未发现 P0–P2 问题。

## 已知边界

上传成功但知识替换因版本冲突被拒绝时，独立素材按人手原件保留，不自动删除；其引用查看与
文件管理由仍开放的 #279 后续子轮完成。本轮通过仅表示工程门禁满足，不扩大为客户验收、
医学批准或生产就绪；仍须以 PR CI 和部署后真实环境复核为准。
