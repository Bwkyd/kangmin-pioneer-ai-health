## 三视角复核

### 患者可懂性

本轮不改变患者端文案、交互或医学内容。门禁失败信息直接指出路径、当前值、上限或存量基线，维护者无需理解体检算法即可定位问题。

### 工程事实

- 独立 CLI、目录总检和 GitHub CI 共用 `scripts/evolution_guard.py`，不存在两套判定口径。
- 新文件必须进入 Git 索引后才属于提交候选；“未跟踪时不见、git add 后拦截”已有真实临时仓库测试。
- 存量缩小时强制同步收紧或移除豁免，覆盖“先改善、后长回旧额度”的变式。
- 过期日只取系统日期，CLI 不提供覆盖入口；缺少责任元数据或配置损坏均 fail-closed。
- `src` 完整检查与真实 Chromium E2E、`legacy` 完整检查均通过，业务代码未改动。

### 医学安全

未修改 `vault/truth/`、临床规则、问卷判定、方案匹配或患者数据路径。完整回归覆盖高危 fail-closed、身份隔离、已审核方案与患者/后台浏览器主路径；没有把结构门禁结果提升为医学事实。

## 剩余边界

本门禁防止可机械判断的结构退化，不证明存量大文件已经完成拆分，也不替代代码评审。生产数据库与服务在开工时另行只读核验；本次没有业务代码差异，因此不应为了形式重复部署相同制品。
