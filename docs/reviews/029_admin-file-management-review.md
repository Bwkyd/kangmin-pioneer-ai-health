# 管理后台文件管理元反思与交付前复核

> 日期：2026-08-26
> 基线：`main@ef8df00` 加 `codex/issue-279-file-management` 当前实现。
> 对象：二级文件管理入口、权威引用读模型、全状态删除保护和双视口回归。

## 患者可懂性视角

文件管理只面向运营后台，患者端没有新增入口或暴露文件 ID、知识状态等内部信息。运营文案明确
新增和替换应回到文章、视频或 AI 知识任务，使用中文件同时说明去向与状态。未发现 P0–P2 问题。

## 工程事实视角

首轮发现一项 P2：PostgreSQL 契约只锁住直接内容文件与知识源引用，尚未单独覆盖封面和正文
附件两个查询变式。现已补齐四种角色、全状态计数和引用明细断言；GitHub CI 将在 PostgreSQL 16
运行该契约。本机 SQLite 测试证明下架视频仍阻止删除，显式移除引用后才可删除。

服务端一次批量读取全部引用，列表不依赖浏览器拼接；删除在仓储事务内重新检查所有状态引用，
不再静默断开草稿、下架内容或停用知识。真实浏览器覆盖文章封面、正文附件、视频、AI 知识与
未使用文件，贯通禁删和真实删除；完整 `npm run check` 通过。修复后未发现 P0–P2 问题。

## 医学安全视角

本轮不修改问卷、证型、分期、方案、穴位、疗法、患者回答或临床 truth；文件状态也不会被提升
为医学裁决。未发现 P0–P2 问题。

## 元反思与边界

sequential-thinking 六步复核了全状态引用、事务保护、封面/正文/知识变式、SQLite/PG 等价和
旧停用语义，确认未把“删除禁止”错误扩大为“所有状态均禁止停用”。列表读取不是事务快照，
并发变化可能在页面上短暂显示旧去向，但真正删除会再次执行服务端守卫，不会仅凭页面状态删除。
正文附件仍使用既有 URL 约定；本轮通过不扩大为客户验收、医学批准或生产就绪，仍须等待 PR CI
和部署后真实环境复核。
