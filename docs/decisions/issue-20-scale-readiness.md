# Issue #20：VAS、TNSS、RQLQ 量表就绪性结论

## 当前真实状态

客户资料只出现“VAS、TNSS、RQLQ 量表”三个名称，没有提供：

- 具体版本和适用年龄；
- 完整题目、选项及回顾时间；
- 计分公式和解释区间；
- 中文翻译来源及电子化使用授权；
- 缺失值和同日重复记录规则。

因此当前材料不足以开发 #41。开发方不能凭常识补写题目，也不能把某篇论文中的版本默认为客户批准版本。

## 1. 量表版本与题目

### VAS

“VAS”可以表示单一总体症状，也可以分别评价鼻部症状、眼部症状、睡眠或生活影响；范围也可能写作 0～10 或 0～100 mm。

需要冻结：

- 本项目评价的具体问题；
- 0 和最高分的文字锚点；
- 回顾时间；
- 适用年龄及监护人代填规则。

### TNSS

公开资料中存在不同 TNSS 用法。常见候选是鼻塞、喷嚏、流涕、鼻痒 4 项，各 0～3 分，总分 0～12；但仍需确认即时评分、过去 12 小时或其他回顾时间，以及中文措辞。

需要客户提供或批准：

- 正式中文题目；
- 0～3 每一级的完整含义；
- 回顾时间和填写频率；
- 儿童是否允许监护人代填。

### RQLQ

RQLQ/mini-RQLQ 属于需要确认版本、翻译和使用许可的标准化工具。当前项目没有官方题本或电子化授权证明。

一期建议：RQLQ 暂不启用。取得正式中文版本及当前产品场景的电子化许可后再开发，不能从网络或论文复制完整题目。

## 2. 计分和解释

- 服务端必须按量表定义版本重新计算，不接受客户端直接上传总分。
- 原始答案、定义版本、计算结果和时间戳一起保存。
- 未经批准不得把分数自动解释为诊断、疗效或治疗建议。
- VAS/TNSS 的展示区间和变化阈值必须由客户导师或临床负责人批准。
- RQLQ 的计算和解释必须严格采用获许可版本随附规则。

## 3. 授权门禁

每个可发布量表必须保存：

- 量表名称、版本、语言和适用年龄；
- 权利人或公开来源；
- 许可类型、许可文件或依据；
- 是否允许电子化、商业/非商业使用及改编；
- 获批题目、选项、公式和解释文案的校验和；
- 临床审核人和发布时间。

缺少任一关键项时保持 `draft`，用户端不可填写。

## 4. 缺失值与同日重复记录

候选结论：

- 缺失答案保持 `missing`，不得当作 0；量表要求完整时不生成总分。
- 每次提交生成独立、不可覆盖的记录。
- 同日可重复填写，保留全部原始记录和时间戳。
- 日历默认显示当天最后一条“完整且有效”的记录；用户可展开查看当天全部记录。
- 删除采用可审计的逻辑删除；重新填写不覆盖旧记录。

## 一期建议

1. RQLQ 延期，直到取得正式中文版本和电子化授权。
2. VAS、TNSS 在收到确切题目、选项、回顾时间和解释口径后开发。
3. 可先实现版本化量表引擎骨架，但不得内置或发布未经批准的题目。

## 仍需客户提供

只需要一份最终材料包，而不是重新填写问卷：

1. 一期启用哪些量表；
2. 每个量表的正式题目、选项、回顾时间和计分规则；
3. 适用年龄和代填规则；
4. 授权或可使用依据，以及批准人和日期。
