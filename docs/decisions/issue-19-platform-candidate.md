# Issue #19：一期技术路线候选（待项目方确认）

## 当前真实状态

- 客户资料称产品为“抗敏先锋小程序”，但没有提供微信 AppID、主体、业务域名、登录方式或发布账号。
- 当前仓库是 React/vinext 的响应式 Web/H5，不是原生微信小程序代码。
- 当前后端目标是 Cloudflare Worker；仓库已有 Sites 项目 ID，但 D1 和 R2 绑定均为 `null`。
- 当前模型代码接入 DeepSeek V4 Pro；知识检索服务尚未实现或选定。

因此不能把当前 H5 冒充为已交付微信小程序，也不能把尚未创建的 D1/R2、身份或检索资源说成可用。

## D-007：客户端形态

候选结论：

1. 一期先交付响应式 H5，复用当前代码完成真实业务闭环。
2. 代码保留 `ClientAdapter` 边界，不直接依赖浏览器身份作为业务用户 ID。
3. 若客户提供合规的微信主体、AppID、业务域名和发布账号，再选择：
   - 小程序 `web-view` 承载 H5；或
   - 单独开发原生小程序壳并复用同一 API。
4. 未完成微信真机和审核验证前，只称“H5 体验版”，不称“原生小程序已交付”。

待确认：□ 一期 H5　□ 一期必须原生小程序

## D-008：用户身份

候选结论：

1. 未登录用户可完成一次性评估，但默认不保存可跨设备查询的健康历史。
2. 保存历史、量表、导出或删除数据前必须建立服务端用户身份。
3. 身份服务使用供应商无关的内部 `userId`：
   - 原生小程序：微信 `OpenID` 只作为外部身份映射；
   - H5：采用经验证的手机号登录，或客户指定的统一身份服务。
4. 不满 14 周岁的被评估者必须关联已验证的监护人账户；不能由设备 ID 代替监护关系。
5. 后台管理员使用独立身份域和 RBAC，不与普通用户登录混用。

待确认：□ H5 手机号　□ 微信 OpenID　□ 客户已有身份服务

## D-009：D1/R2 与环境

候选结论：

1. 沿用当前 Cloudflare 架构：
   - D1 保存结构化业务数据、版本和审计；
   - R2 保存视频、封面、图片和知识源文件。
2. `integration`、`staging`、`production` 使用不同数据库、存储桶、密钥和域名。
3. 本地只使用合成数据；禁止复制生产健康数据到测试环境。
4. 在客户确认 Cloudflare 账号、费用和数据责任前，不创建或声明生产资源。
5. 当前 `.openai/hosting.json` 的 `d1: null`、`r2: null` 是明确阻塞证据。

待确认：□ 使用 Cloudflare D1/R2　□ 改用客户指定基础设施

## D-010：模型与检索供应商

候选结论：

1. 一期继续通过服务端模型网关调用 DeepSeek V4 Pro，仅用于候选提取和通俗解释。
2. 领域代码只依赖结构化模型接口；不得直接依赖供应商 SDK 或让模型决定医学规则。
3. 知识检索采用适配器：
   - D1 保存文档、切片、版本、审核状态和引用元数据；
   - 向量索引供应商在 staging 真实评测后再冻结；
   - 任何检索结果都必须回查 D1 的已发布来源并通过引用校验。
4. 模型或检索不可用时，固定规则结果仍可返回；不能用模型自身知识补齐。
5. 生产前必须确认 API 账号、费用承担、数据处理区域和健康数据发送边界。
