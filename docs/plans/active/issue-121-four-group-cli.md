# Issue #121：设计四组 CLI 内核并建立薄前端边界

## 目标

只以当前未关闭的客户 Issue 为功能输入，把业务能力收敛为四组 CLI 命令，其中 `consult`、`health` 为核心，`content`、`control` 为次要；前端后续调用同一应用服务，不复制业务规则。

## 范围

- 盘点 #69、#70、#71、#88～#99、#101。
- 固定四组命令的职责、发现方式、JSON 契约和退出码。
- 首先实现可执行的能力目录和阻塞检查。
- 临床候选内容只登记和展示审批状态，不作为正式方案输出。

## 非范围

- 不把已关闭 Issue 自动恢复到新架构。
- 不直接导入或迁移 `legacy/` 业务代码。
- 不批准临床规则，不接入真实花粉数据源。
- 本任务不合并、不部署，也不关闭客户 Issue。

## 验收标准

- [x] 顶层业务命令严格为 `consult`、`health`、`content`、`control`。
- [x] 两个核心组和两个次要组在帮助及机器输出中可识别。
- [x] 每个范围内 Issue 都有命令归属，或明确标记为聚合 Issue。
- [x] `--json` 的 stdout 是稳定 JSON，错误使用确定性退出码。
- [x] 临床待确认和外部数据待确认能力默认 fail closed。
- [x] 新代码不导入 `legacy/`。
- [x] `npm run build`、`npm test`、`npm run lint` 通过。
