# Issues #72/#76/#80/#81/#102/#103：健康档案与过敏原记录前端

## 目标

完成第一轮移动端用户路径：将健康档案与症状记录分开，并提供按日期填写、保存、编辑、查看过敏原患者自述及回到健康档案追溯诱因的前端闭环。

## 范围

- “我的”中的健康档案与症状记录进入不同页面。
- 健康档案展示基础信息、过敏史、常见诱因和用药记录入口。
- 过敏原记录按五类场景分组、多选，保留未识别因素和其它描述。
- 症状日期与过敏原患者自述记录互相可达。
- 通过同源服务端会话调用类型安全的最小健康记录 fetch 适配器。
- 渲染、交互逻辑与本地浏览器验证。

## 非范围

- 数据库、迁移、后端 API、服务端身份实现和用药记录实现。
- 花粉监测、花粉监测入口或花粉监测假数据。
- 生产后台、推送、部署、Issue 关闭、PR 或合并。
- 自动判断过敏病因、诊断或治疗建议。

## 验收标准

- [x] 健康档案与症状记录的入口、标题和返回路径不混淆。
- [x] 健康档案至少包含基础信息、过敏史、常见诱因和用药记录入口。
- [x] 过敏原按环境暴露、接触性物质、饮食与作息、活动相关、其他分组，并支持多选与其它描述。
- [x] 可从症状日期进入同日期过敏原记录，记录明确为患者自述且不判定因果。
- [x] 保存、编辑、删除与历史 UI 只在后端真实成功后更新，并明确 401/404/未接后端时的失败状态。
- [x] 前端请求不发送 `x-user-id`，由同源服务端会话解析身份。
- [x] 既有对话、症状日历、免责声明和移动端布局保持可用。
