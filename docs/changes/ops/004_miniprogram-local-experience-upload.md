## 实现与验证

客户体验配置在正式微信登录关闭时，将隐私授权、健康档案、症状、过敏原、用药、概览、
日历和趋势保存到当前设备缓存，不调用 `wx.login`，也不上传或迁移为正式患者档案。正式
微信登录开启后仍使用原服务端身份与记录链路。问助手删除页面内重复的评估摘要和对话工具栏，
但保留标题栏抽屉中的聊天记录与新建入口。

页面链路测试覆盖“本机授权→保存症状→日历/趋势→我的页回显”，并断言 0 次登录和 0 次网络。
小程序窄测 26/26；完整 `cd src && npm run check` 通过，包含类型、架构、小程序清单、正式身份、
服务端患者记录和真实 Web 浏览器 E2E。sequential-thinking 复核后补齐重复提交重放、同键不同内容、
未来日期和 TNSS 越界变式。`km-review` 的患者可懂性、工程事实和医学安全三视角 P0、P1、P2 为 0。

PR #265 的 `quality`（3 分 06 秒）和 `image`（38 秒）均成功；状态记录 PR #266 的 `quality`
（3 分 21 秒）和 `image`（42 秒）也成功。

## 隔离预览与上传

复用唯一临时项目 `/tmp/kangmin-miniprogram-avatar.EnY69S`，没有再次执行 `cli open` 或打开并排窗口。
从仓库同步小程序源码时排除 `project.config.json` 和 `project.private.config.json`，只在临时项目保留
作者确认的 AppID；仓库 AppID 继续为空，未写入 AppSecret 或患者数据。

首次全量同步曾以仓库空 `project.config.json` 覆盖临时 AppID，微信预览因此在进入业务编译前返回
“不存在此 AppID”。恢复临时 AppID，并改为显式排除项目身份配置后，真实预览编译成功，包体
825,437 字节；从合并后的 `main` 再同步并上传开发版 `0.1.11`，包体 823,467 字节。
