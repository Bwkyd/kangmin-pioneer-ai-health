# ops/001 原生小程序 CLI 上传验证与关闭服务端口

## 执行概述

- 时间：2026-08-18
- 执行人：Codex；作者明确授权开启本机 CLI 服务端口
- 环境：macOS、微信开发者工具 36.6.0、AppID `wxec3aeaadcddaf45e`
- 结果：版本 `0.1.0` 的上传接口返回 `success: true`，包体 `136523` 字节；未部署 Web 服务端

## 步骤一：先做工程检查

在仓库工程中运行 `cd src && node scripts/check-miniprogram.mjs`。工程
`src/miniprogram/project.config.json` 的 AppID 保持为空，仓库中没有 AppSecret。

## 步骤二：隔离上传副本

复制 `src/miniprogram` 到临时目录，只在临时副本的 `project.config.json` 注入作者提供的 AppID。
上传副本不进入 Git，上传结束后移入本机临时回收目录；仓库工程和业务代码没有被凭据改写。

## 步骤三：登录并执行上传

作者允许开启微信开发者工具本机 CLI 服务端口后，重启工具并运行 `cli islogin`，回读为
`{"login":true}`。直接运行工具自带的 `cli upload` 首次失败，原因不是业务代码，而是当前
36.6.0 CLI 子命令没有把二维码输出参数传给上传请求。

随后使用同一已登录的本机 CLI 服务端点，显式传入临时工程、AppID、版本、描述、有效的二维码
输出路径和信息输出路径。`/v2/upload` 返回：

```json
{"success":true,"info":{"size":{"total":136523,"packages":[{"name":"TOTAL","size":136523}]}}}
```

## 步骤四：关闭本机服务

上传完成后关闭所有相关配置档的 CLI 服务端口并退出微信开发者工具；用 `lsof` 复核端口
`49606`、`51347` 均无监听，配置值为关闭或空值。未把本机服务端口留给后台运行，也没有保存
登录凭据或 AppSecret。

## 坑记录

### 工具自带 `cli upload` 的参数传递缺陷

当前 CLI 的上传子命令没有完整转发二维码输出参数，直接调用可能返回“二维码输出路径无效”，
即使命令带有 `--info-output` 也不能把它当作二维码输出路径。排障时应查看实际请求和服务端
返回，不以命令是否启动或退出码单独判断上传成功。

### 上传接口成功的含义有限

`success: true` 只证明微信上传接口接受了这次代码包；不证明体验版已经对外可见，也不证明
真实微信登录、合法域名、真机网络/隐私链路、审核发布或客户验收已经完成。
