# arch/003 单管理员内容治理后台

## 背景与动机

报价范围要求管理科普文章、视频和智能体知识资料，并追加了调理方案、操作步骤及视频绑定。原仓库只有 H5 演示和空 D1 schema，无法提供真实的内容发布闭环。

## 技术选型

| 领域 | 选择 | 原因 |
| --- | --- | --- |
| 结构化数据 | Cloudflare D1 | 支持状态、版本、关联、去重与审计查询 |
| 文件 | Cloudflare R2 | 视频、图片和知识来源不进入数据库 |
| 管理身份 | 单账号 + PBKDF2 + HMAC 会话 | 符合一期单管理员范围，不保存明文密码 |
| 通知 | 站内消息 | 不依赖微信或短信资质 |
| 知识检索 | Vectorize/Embedding 适配器 | 只索引已治理来源，不改变固定临床规则 |

## 数据模型

- `content_items` 统一表达文章、视频、知识和方案的草稿、发布、下架和版本。
- `media_assets` 保存 R2 对象键和可检索元数据；`plan_steps` 保存有序操作步骤与媒体绑定。
- `notifications` 与 `notification_reads` 分离通知内容和用户已读状态。
- `audit_logs` 和 `idempotency_keys` 分别保证写操作可追溯与重试安全。

## 架构设计

- `/api/admin/*` 同时执行服务端会话验证与审计，前端隐藏按钮不作为权限边界。
- 文件先写 R2，数据库失败时删除新对象；发布状态、消息和审计通过 D1 batch 一次提交。
- 用户端查询固定限制为 `published`；媒体读取还需回查已发布内容的关联。
- 知识发布前要求已完成索引；方案发布前要求风险、禁忌、已批准证型、步骤与已发布视频。
- schema 同时提供 Drizzle 迁移和幂等运行时初始化，保证本地、staging 与 Sites 托管环境一致。
