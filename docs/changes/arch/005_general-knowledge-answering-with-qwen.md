# arch/005 知识问答使用千问并恢复一般科普回答

## 背景与动机

正式知识问答默认绑定 DeepSeek，但当前环境实际配置和实验验证使用千问，导致只修改提示词并不能
进入真实调用链。旧医学发布门又会把没有检索来源的一般病理解释整体降级成“资料不够”，与作者
确认的“无命中也允许模型正常回答”不一致。

## 技术选型

| 方案 | 结果 |
| --- | --- |
| 继续使用未配置的 DeepSeek | 运行时只能固定降级，放弃 |
| 增加关键词输出薄门 | 实验 018 误拦且过拟合，放弃 |
| 千问 + C 版系统提示 + 现有硬事实发布条件 | 采用；复用已有密钥和关闭思考配置 |

## 架构设计

- 同一个千问适配器承担知识问答、方案转译和方案后追问，但三条任务使用各自系统提示。
- 知识检索命中时提供 Top-3 来源；零命中仍允许一般概念、原因和区别回答，不伪造来源。
- 一般病理因果只在非个人、非处方句中放行；个人诊断、孕期禁忌、无依据数字和医学动作仍走
  原医学发布条件。
- 回答保持整段原子校验，不做可能改变语义的逐句删除拼接；任何不可发布内容仍使整段降级。
- 明确呼吸困难、喘不上气、胸闷憋气、口唇发紫、意识异常或剧烈胸痛在检索与模型前固定分流。
  单纯询问“胸闷是什么/是否相关”不误判为正在急症。

## 相关文件

- `src/infrastructure/qwen-plan-dialogue-adapter.ts` — C 版知识提示和真实千问调用。
- `src/modules/agent/knowledge-qa.ts` — 零命中生成、逐句发布与降级。
- `src/modules/agent/emergency-routing.ts` — 两条患者对话入口共用的急症分流。
- `src/modules/agent/medical-publication-gate.ts` — 一般知识因果的窄作用域。
- `src/app/composition-root.ts` — 正式默认端口改用千问。

## 验证与限制

真实组合根在空知识库下完成一般鼻塞原因和急症两条命令；独立 4 题真实模型冒烟中 3 道一般题
正常回答、急症零模型固定分流。完整 `npm run check` 通过，402 项 Node 测试为 326 通过、0 失败，
76 项 PostgreSQL/S3 外部资源测试按既有条件跳过，真实浏览器 E2E 通过。

这次变更不表示一般医学内容均经专家核验。旧门曾把“打喷嚏”中的“喷”误当成处方动作，导致正常
因果句被拒；本轮修正为只用完整的个体/动作表达限制一般因果，并补了相应变式。后续仍应以历史
真实对话评估回答质量，不再靠无限增加提示词或正则补丁解决。
