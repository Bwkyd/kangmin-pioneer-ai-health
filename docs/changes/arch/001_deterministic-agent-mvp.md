# arch/001 确定性鼻健康智能体 MVP

## 背景与动机

原页面含有尚未接入的知识库、证型和方案演示，无法证明真实智能体链路已经成立。本次先交付可运行的内部测试 MVP：规则负责判断，模型只做可确认的信息提取，并在任何外部能力缺失时安全降级。

## 技术选型

| 决策点 | 选择 | 原因 |
| --- | --- | --- |
| 临床判断 | 固定 TypeScript 规则 | 可穷举、可追溯，不让模型改变规则 |
| 模型职责 | DeepSeek V4 Pro 仅提取候选字段 | 候选必须由用户确认，越权输出直接拒绝 |
| 服务形态 | `extract`、`evaluate`、`explain` 三个无状态 API | MVP 不保存健康文本，便于隔离测试 |
| 失败策略 | 固定模板和手工结构化问卷 | 未配置或调用失败时仍能完成规则评估 |
| 集成验证 | 生产构建 + 完整服务 HTTP E2E | 验证真实路由，而不只验证纯函数 |

## 数据模型

- 所有问卷字段使用 `yes | no | unknown` 三态值，`unknown` 不得当作 `no`。
- 判断顺序固定为：高风险安全门禁 → 适用资格 → 严重度 → 证型。
- 证型输出包含规则包版本、规则编号和匹配事实。
- 当前没有经审核方案，分类成功也只能返回 `no_approved_plan`。

## 架构设计

1. 服务端严格校验完整输入，并重新计算规则，不接受前端提交的证型结论。
2. 任一高风险项命中立即停止后续判断；冲突、无命中和信息不足均不猜测。
3. DeepSeek 使用 JSON 输出、非思考模式、10 秒超时和最多一次重试；输出 schema 越权时按模型不可用处理。
4. 当前未接入经审核知识库，因此解释接口使用固定边界文案，不调用模型生成医疗方案。
5. 请求长度、每分钟次数和模型并发均受限；单实例内存限流明确只适用于 MVP。
