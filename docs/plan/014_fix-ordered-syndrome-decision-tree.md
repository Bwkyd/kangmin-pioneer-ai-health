# 修正有序六步证型决策树

- 状态：已实施、提交并部署客户试用环境，等待客户验收
- 日期：2026-08-09
- 代码基线：`50df413`；部署提交：`eba184f`；draft PR：#188
- 客户依据：`vault/truth/clinical/syndrome-six-step-decision-tree.md`

## 目标

把现有并行匹配的 v3 七规则替换为严格有序、命中叶子即终止的六步状态机，使
CLI、HTTP 和 Web 对同一选项序列给出完全一致的证型。第 1/6 步 Q10、第 2/5 步
Q8 必须按节点分别存储，不能因题面相同而复用答案。

## 非目标

- 不在本次重写急性期/缓解期算法、危险信号、确诊门禁或成人/儿童分流；
- 不修改客户提供的方案正文、方法选择关系或医学禁忌；
- 不把证型人群占比写成诊断配额；“肾阳不足约 10%”只用于上线后异常监测；
- 不允许模型根据自由文本直接决定跳转或证型。

## 依据与优先级

1. 新增 truth 六步树负责证型主判定；
2. `vault/truth/clinical/assessment-rules.md` 仍负责其未被替代的通用、安全和期别规则；
3. `vault/raw/product/页面展示.md` 负责题面、选项和结果页表达；
4. `vault/raw/clinical/急性期方案、调体方案（缓解期方案）.md` 负责叶节点后的可选方法；
5. v3 七规则和现有 benchmark 仅作反向回归证据，不得覆盖客户确认规则。

## 已确认缺陷

- 现有实现把 Q8/Q9/Q10 的 B 错误压成 `yes`，导致 Q10B 提前判肺经伏热、Q8B
  提前判脾气虚弱、Q9B 错判肾阳不足；
- 规则引擎并行计算 T1–T5，无法表达“上一节点未命中才进入下一节点”；
- 原实现以同一症状字段保存重复题，不能同时保存首次回答和二次确认；
- 当前 12 场景 benchmark 以错误的 v3 规则生成期望值，测试全绿不能证明符合客户树。

## 实施设计

### 1. 版本与节点身份

发布新的规则包版本。为六个节点使用稳定身份：`step1_q10`、`step2_q8`、
`step3_q6`、`step4_q9`、`step5_q8_confirm`、`step6_q10_confirm`。答案保存为节点
身份 + 原始选项 A/B/C，不再先转为症状布尔值。

### 2. 唯一确定性状态机

在应用服务下建立单一状态机，输入当前节点与节点答案，输出下一节点或叶子证型。
CLI、HTTP、Web 全部复用该服务；DeepSeek 只能把自然语言提取为受控选项候选，
经患者确认后才提交状态机。

规范跳转：

| 节点 | A | B | C |
| --- | --- | --- | --- |
| `step1_q10` | 肺经伏热 | `step2_q8` | `step2_q8` |
| `step2_q8` | 脾气虚弱 | `step3_q6` | `step3_q6` |
| `step3_q6` | `step4_q9` | `step4_q9` | `step4_q9` |
| `step4_q9` | `step5_q8_confirm` | 肺气虚寒 | 肺气虚寒 |
| `step5_q8_confirm` | 肾阳不足 | `step6_q10_confirm` | `step6_q10_confirm` |
| `step6_q10_confirm` | 寒热错杂、虚实并见 | 肾阳不足 | 肾阳不足 |

Q1/Q2/Q5/Q7/Q11 只生成辅助印证信息，不得覆盖叶子结果。

### 3. 持久化与兼容

- 复核后确认现有 SQLite、PostgreSQL 表的主键均为 `(session_id, field_code)`；以稳定
  节点身份作为 `field_code` 即可独立保存六个答案，无须冒险重建数据表；
- 会话详情、历史恢复和决策凭证返回节点身份、中文答案及规则版本；
- 新规则发布后不续跑旧规则未完成会话：明确提示新建评估；试用环境旧会话仅在备份
  后按既有部署流程处理；
- unknown 不等于任一医学选项，保持当前节点并进入澄清，不允许静默放行。

### 4. 实施顺序

1. 先写六步状态机及 111 路径穷举测试；
2. 改答案模型与仓储写入，核验 SQLite 实存和 PostgreSQL 契约；
3. 让会话服务、CLI/HTTP/Web 共用状态机并修复历史恢复；
4. 重写 benchmark 期望来源，补关键错误路径和 unknown；
5. 完成全量检查、浏览器 E2E、备份与试用环境部署核验。

## 验收标准

- 穷举全部 **111 条根到叶 A/B/C 路径**，逐条验证题序、跳转、未进入节点不出现、
  叶节点立即终止、二次确认独立留痕及五类结果；
- 重点回归：Q10A 首步立即肺经伏热；Q10B/C 不提前结束；Q8B/C 不提前判脾虚；
  Q9B/C 必为肺气虚寒；
- Q1/Q2/Q5/Q7/Q11 的任意辅助答案不能改变已经确定的叶子证型；
- CLI、HTTP、Web 对相同节点答案序列输出一致；刷新、切换历史后节点、中文答案和
  结果不变；
- unknown 保持未决并补充澄清；旧版本未完成会话不能混入新规则继续；
- SQLite 实存测试与 PostgreSQL 仓储契约测试一致通过；
- `npm run check`、`python3 scripts/structure-lint.py .`、`git diff --check` 和浏览器
  E2E 全部通过后，才允许部署。

## 风险与限制

- 数据模型变更涉及双数据库和历史会话，必须先备份、再迁移、后核验；
- 现有 v3 测试可能把错误行为固定为期望值，需逐项按新 truth 重写，不能机械改绿；
- 本计划只修证型主树，急性/缓解期等仍按当前独立规则运行，其医学口径需另行确认。
