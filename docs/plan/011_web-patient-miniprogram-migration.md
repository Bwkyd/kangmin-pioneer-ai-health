## 本轮实现与验证结果

- 新增健康档案页，覆盖基础资料、过敏原暴露、用药记录、授权门禁、保存版本和失败态。
- 助手改接 `/v1/patient/agent/stream`，前端按增量内容渲染，支持中断、重试、历史会话和错误回收。
- 科普页补齐文章/视频/方案/知识问答、媒体与长正文展示，并按 Web 的成人/儿童、分区和分类导航过滤。
- `cd src && npm run check` 通过：361 项测试，285 项通过、0 项失败、76 项因本机未配置 PostgreSQL/S3 按约定跳过；真实浏览器 E2E 通过。
- `cd src && node scripts/check-miniprogram.mjs` 通过；小程序定向测试 14/14 通过；开发者工具 36.6.0 对临时副本预览通过，包体约 179.5 KB。
- 开发者工具自带 `cli upload` 仍因 36.6.0 未转发二维码输出参数而返回“二维码输出路径无效”；本轮不把该失败误报为上传成功，也不修改业务代码绕过工具缺陷。
- 同版本附带的 `wechatide` 上传入口需要单独的客户端授权，未自动继承现有 CLI 登录态；本轮未触发扫码授权，未生成体验版信息或二维码。

流式输出的安全边界：服务端仍先完成规则校验、输出校验和持久化，再把已校验的回答分片下发，
因此本轮保证的是患者端的增量呈现、可中断和可恢复，不承诺模型 token 在校验完成前就提前展示。
如果真机有“首字节仍慢”的体验问题，应另开安全架构评审，不能为追求速度直接放行未经校验的模型输出。

## 验收门禁

- 流式助手发送后应立即进入处理态；服务端完成规则/输出校验后再出现回答增量，最终 `done` 内容
  与增量拼接一致；中断时明确提示并可恢复，不把未经服务端校验的模型 token 展示给患者。
- 登录失效、未授权、网络失败、空数据和服务不可用不得伪装成空档案或空历史。
- 管理后台发布文章、视频、知识后，小程序可见；下架后不可见；患者端和管理端权限不串线。
- 客户微信作为体验成员扫码，完成首页、助手、授权、记录、健康档案、内容、视频、消息的
  真机路径后，才进入删除 Web 患者入口的独立收尾变更。
- 体验版上传需要升级/修复本机开发者工具 CLI，或按既有运维记录使用经核验的上传服务端点；上传成功后仍需作者发车冒烟和有界验收。

## 后续收尾边界

客户验收前不删除 Web 患者端。验收通过后另开变更，仅移除患者 Web 入口/页面，保留管理后台、
患者 API、数据库、媒体和回滚 release；正式域名、合法域名、隐私配置和发布主体由客户准备。
