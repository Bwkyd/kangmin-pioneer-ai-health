# 取舍卡 · 通用 Agent 设计应该怎么收口

> 2026-08-21。作者已否定“成人/儿童/患者/公益团队模式路由”。以下选择按新方向重写。

> 冒烟实验 `docs/experiments/002_general-agent-workbook-smoke.md` 已证明无模式通用 Agent 的体验方向成立，但未经证据用途过滤和 claim 级输出门禁的 B 原型不安全；因此“选 B”不等于立即开发，先完成第二轮离线安全门禁实验。

## 我的首选方案

做一个**通用、连续、能自我判断语境的鼻健康 Agent**：

```text
稳定工作手册
      + 当前会话/已确认事实/规则结果/当前方案
      + 只读知识搜索工具
      ↓
模型自己判断：直接回答 / 搜索后回答 / 追问 / 解释 / 安全退出
      ↓
结构化响应 envelope → 服务端医学校验 → 持久化 → 流式发送
```

这才是从 Pi/DSH 借来的核心：稳定前缀、按需能力、动态上下文、可重建请求；不是照搬 coding agent，也不是继续堆产品模式。

## 需要作者拍板的选择

### 选择一：允许模型使用多少自身常识？

| 选项 | 做法 | 我的建议 |
|---|---|---|
| A | 任何医学事实都必须来自批准知识；无证据只追问/降级 | 最安全，但会保留当前“很死”的感觉 |
| B | 低风险、非个体化的一般解释允许使用模型后训练知识；诊断、方案、参数、禁忌和疗效必须有批准证据 | **推荐**：开放语言层，封住医学动作层 |
| C | 允许模型自由使用自身医学知识，只有明显危险词才拦截 | 不推荐：不可追溯，容易出现流畅但错误的医学细节 |

我建议选 **B**。这不是放弃知识库，而是把知识库从“能不能说话的开关”改成“医学细节和来源的依据”。

### 选择二：知识库怎么被调用？

| 选项 | 做法 | 我的建议 |
|---|---|---|
| A | 服务端每轮自动检索，模型不能主动决定 | 改造最小，但仍容易检索错问题 |
| B | 给模型一个 `search_approved_knowledge` 只读工具，由模型判断何时搜索，服务端限制查询范围、条数、来源和结果 | **推荐**：最接近 Pi/DSH 的 Agent 边界 |
| C | 让模型自行读 raw Markdown/文件系统 | 不允许：权限和来源不可控 |

推荐 **B**。工具返回的是证据，不是规则；工具本身不能写数据、访问外网或执行命令。

### 选择三：手册是否全量进入索引？

| 选项 | 做法 | 我的建议 |
|---|---|---|
| A | 只选少量患者白话片段入库 | 容易继续答不到问题，失去手册价值 |
| B | 手册全量可检索，但每个片段带来源、章节、风险和 `allowed_use`；检索全量，输出按用途校验 | **推荐**：资料不封死，展示不越权 |
| C | 全量文本直接放 system prompt | 不推荐：上下文浪费、版本难管、模型容易混用章节 |

这里的 `allowed_use` 是资料权限，不是用户模式。需要作者/医学负责人确认哪些章节可以直接对外表达，哪些只能作为内部参考或规则依据。

### 选择四：要不要直接移植 Pi/DSH？

| 选项 | 做法 | 我的建议 |
|---|---|---|
| A | 继续在现有代码中补一个最小 Agent loop、工作手册、只读工具和统一输出 | **推荐**：最快验证产品体验，保留现有规则和会话 |
| B | 先做一个离线 harness 回放器，验证 15 条问法后再接线上 | 推荐作为首轮实验，风险更低 |
| C | 把 Pi/DSH runtime 整体接进项目 | 不推荐：成本大，不能解决医学真相问题 |

我的建议是 **B → A**：先离线回放，再在现有服务内实现最小闭环。

### 选择五：来源如何出现给用户？

| 选项 | 做法 | 我的建议 |
|---|---|---|
| A | 每句话后都附来源 | 透明但会很机械 |
| B | 正文自然回答，末尾提供简短“参考依据”入口；需要时展开来源 | **推荐**：兼顾小荷式体验与可信度 |
| C | 不展示来源，只在后台记录 | 最自然，但比赛展示与医学解释说服力弱 |

## 我建议你只拍板三件事

1. **选 B 还是 A：是否允许低风险一般解释使用模型后训练知识。** 我的建议：B。
2. **是否同意只读知识工具由模型主动调用。** 我的建议：同意，但后端只给批准资料。
3. **是否同意手册全量索引、按片段用途控制输出。** 我的建议：同意；这不是成人/儿童/患者路由，而是资料治理。

“做不做完整 Pi/DSH 移植”不需要拍板，我建议直接不做。

## 三个主要风险

- B 选项下“低风险”如果没有书面判据，会逐步扩大成任意医学回答；需要输出 validator 和样本走查。
- 全量索引如果没有 `allowed_use` 与版本信息，会把儿童、禁忌、操作细节等章节误带入普通回答。
- 模型主动调用工具如果没有调用日志、超时和空结果降级，会比当前固定拒答更难排错。
