# 取舍卡 · 用评测驱动的上下文工程降低患者 Agent 无依据补全

> 2026-08-21。最后一栏留给作者拍板。

## 不可妥协的三条

1. 不能以降低“瞎编”为名把普通问答重新做成拒答产品。
2. 模型每轮应看到最小但充分的高信号证据、来源角色、患者事实和未知项。
3. 所有改进必须在未见题、多次试次上同时证明有用性、依据性、风险和性能。

## 我选择什么

把“评测驱动的上下文工程”作为主路线：运行时保持一个通用 Agent，由模型按需语义检索；
系统只向它提供紧凑工作宪法、当前会话事实和带来源角色的相关知识。设计时用持续评测选择
模型、提示词和上下文组合，不让运行时后端逐句扮演医学裁判。

## 我放弃什么

放弃继续堆提示词条款、整本手册注入、原始 Top-k 无差别注入，以及先建设复杂评测平台；
也不宣称上下文工程可以保证零幻觉。

## 依据

- [x] 自有积累：实验 003 的语义召回和实验 006 的纯提示词上限，均为当前工作树实测。
- [x] 他人积累：两篇 Anthropic 应用 AI 团队文章的评测与上下文工程方法，只借架构。
- [x] 自己跑的：实验 006 促使路线从“继续写 prompt”转为“比较上下文和模型组合”。

## 满意线

首轮不追求“所有医学问题零错误”。满足条件是：20–50 条平衡题集有人工认可参考行为；
低风险回答性不低于当前基线；证据转用途、儿童/孕期、未知药物和急症四类在多次试次中
明显改善；每次失败能从完整记录定位到检索、上下文、模型或判据，而不是归因于“感觉”。

## 支持与反对

最强支持：上下文文章明确把目标定义为最小高信号 token，并建议即时检索与渐进披露；
评测文章建议从 20–50 个真实失败开始，平衡正负样本并用 `pass^k` 衡量客户可见稳定性。
这正好对应实验 006 暴露的“有用但无依据补全”。

最强反对：更好的上下文只提高成功概率，不能提供确定性保证；如果底层模型在医学指令遵循
上能力不足，上下文优化可能只让它更流畅地生成错误。必须设置换模型停止线。

## 仍未补齐的一处

当前缺少经人确认的参考行为：什么算“有依据但不僵硬”的好答案。没有这份小型黄金集，
任何自动评分器都会把自己的偏好冒充产品标准。
