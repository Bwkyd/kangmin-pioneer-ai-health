# 差距表 · 现在缺的不是另一个通用 Agent

| 命门 | 当前状态 | 外部可补什么 | 处理 |
| --- | --- | --- | --- |
| 产品语义检索 | 当前运行时仍是字面 `LIKE`；实验语义 Hit@3 为 10/10 | 向量检索、Top-k 与来源保留方法 | P1：直接实现报价内纵向切片 |
| 自然检索触发 | 当前只在点名当前方案穴位时触发检索 | Agent 按需检索与结构化上下文方法 | P1：按问题语义触发，不建立受众路由 |
| 可复现模型选型 | 已有手写 runner，当前证据足以停止换模型 | Promptfoo 原生矩阵、断言与 CI | P3：需要长期回归时再评估，不阻塞本轮 |
| 医疗行为后训练 | 不在报价范围 | MedicalGPT 提供训练流水线 | 排除：不训练、不租 GPU、不纳入交付 |
| 检索与生成归因 | 已有召回实验，但 claim 级诊断仍手工 | RAGChecker 分开算检索和生成指标 | P2：借指标结构，保留人工医学复核 |
| 中文患者安全基准 | 外部考试/英文风险集与本项目不完全同题 | CMB、HealthBench、MedSafetyBench 提供题集组织方法 | P1：自建鼻健康多轮黄金集，不直接拿外部总分放行 |
| 线上失败飞轮 | 当前没有真实用户 trace、标签和回放入口 | Langfuse 可自托管 tracing/dataset/feedback | P3：真实试用前不增加运维系统 |

## 候选横向取舍

| 候选 | 现在直接用 | 为什么不是首选的其他用途 |
| --- | --- | --- |
| Promptfoo | 暂否；现有题集足够验证本轮改造 | 不是医学裁判，也不进入患者请求链 |
| MedicalGPT | 否，仅保留研究快照 | 训练不在报价范围 |
| RAGChecker | 部分，只借诊断指标 | 现成 LLM entailment 不能替代中文医学人工校准 |
| OpenCHA / MedRAG | 否，只借架构 | 会增加 Python 运行时与外部语料，不解决本项目行为数据缺口 |
| HuatuoGPT-o1 | 暂否 | 许可证未明确，考试推理强也不证明患者边界强 |
| Langfuse | 暂否 | 当前没有生产 trace，先部署平台属于过早建设 |

## 自己跑出的新证据

实验 009 固定患者知识选择管线，只把回答模型换成 `deepseek-v4-pro`。20/20 成功，P01–P05
为 5/5；U02、U03、U04、U05 明确失败，达到 4/10，未满足不超过 2/10 的放行线。因此
“换到更强 API 模型”只能继续作为变量，不能作为解决方案。
