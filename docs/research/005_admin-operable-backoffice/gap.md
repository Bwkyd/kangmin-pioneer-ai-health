# 两类发现 · 如何把现有管理后台从演示型页面收敛为报价内可运营后台，并先做哪一件事

> 2026-08-18。读完两类来源，落成两类发现：**它们做到的** 与 **它们没做的**。
> **分析的成果不是综述，是这两张表。**
> 综述回答「别人做到哪了」，这里回答「**我该先做哪一件**」。
>
> 分级沿用**分级修复**：P0 最高、P3 最低，**P0 / P1 / P2 清零，P3 酌情**——
> 这条线定好了，评审才有出口。

## 一、它们做到的

逐项核对

四态判定，不许用「基本满足」这种含糊说法。

| # | 不可妥协的那条 | 状态 | 差距是什么 | 修起来要什么 | 分级 |
|---|---|---|---|---|---|
| 1 | 报价内文章、视频、知识库三条链可由后台完成并在患者端或 Agent 侧生效 | 部分 | 服务端命令和当前 Web 生命周期已存在；“推送”当前实现为独立站内消息，是否满足报价语义仍需作者确认并写回 truth | 前端接通已有命令、补结果回读；若确认微信订阅通知，则是新增外部依赖与范围，不是小修 | P1 |
| 2 | 运营人员不靠开发者知识也能找到任务、理解状态、处理错误并继续 | 部分 | `AdminApp` 只有一个 section 状态，刷新时并行拉六类列表；首页主要是四个统计和静态三步说明，列表缺少任务队列、搜索筛选、详情路径和清晰的失败恢复 | 在当前 API 上重做信息架构、列表/详情/编辑状态和动作反馈；不需要更换技术栈 | P1 |
| 3 | 管理身份、确认、版本、审计和医学边界不被前端绕过 | 部分 | 服务端已有会话、owner、确认、修订和同源防护；前端只显示角色，缺少对权限拒绝、版本冲突、索引失败等状态的可操作解释 | 保留服务端裁决，补状态映射、权限空态、确认文案和失败回读；不把规则编辑或诊断能力放进后台 | P2 |

**「修起来要什么」这一栏最要紧。** 同样是「缺」，成本差一个数量级：

| 缺法 | 成本 |
|---|---|
| **能力已经有了，只是没接上** | 低成本高收益，优先做 |
| **能力本身就没有** | 要立项，另算 |

判「缺」的时候多走一步，去底层看看是哪一种。

本轮不是在多个成品后台之间选型，而是在“当前后台改造”和“换栈/视觉换肤”之间取舍；横向结论落在 `decision.md`，不重复填空表。

## 二、它们没做的

| 找过什么 | 结论 | 是哪一种 |
|---|---|---|
| `admin-business` 的 BI、4 减 4 增和 100+ 种子数据 | 有但不适用：报价只规定内容/视频/知识库运营闭环，没有经营分析或演示数据要求 | 没顾上做，不是当前缺陷 |
| `admin-business` 的 Next/Neon/Shadcn 全栈模板 | 有但不适用：当前系统已经运行在 Vite/React、既有服务端命令和现有存储上 | 做不到的迁移收益不足，不应作为首项工作 |
| 多级审批、复杂 RBAC、临床规则编辑、用户运营后台 | 明确不属于当前报价；历史计划也把用户、模型中心、临床计划列为后续或暂不扩展 | 范围边界，不是空白机会 |
| `legacy/app/admin/page.tsx` 的旧 API/数据模型 | 只可借鉴“内容/媒体/审计”分组；不得向当前实现导入旧业务 | 历史参考，不能当作当前能力 |

⚠️ **空白是结论，不是失败。**

⚠️ **同样是「没有」，意义相反**：

| | 意味着 | 怎么认出来 |
|---|---|---|
| **没顾上做** | 可能是机会——他们没空，你有 | 从来没人提过、也没人试过 |
| **做不到** | 可能是天堑——多少人试过都撞回来了 | 提交历史里试过又回滚、issue 里讨论过又关掉 |

**空白不都是机会，有些空白是别人替你踩过的坑。**

### 该不该自己跑一个

| 判据 | 结论 |
|---|---|
| 搜一下就有答案 | **不用跑**，去查 |
| 别人做过，只是我没找到 | **先去找** |
| **这道难题多年没解决** | **跑它**——不可能今天拍脑袋解决 |
| 输出清楚，却不知道拿什么喂它 | **跑它**——输入不清楚，正是实验的场合 |

要跑就去 `docs/experiments/` 开一个 `expNNN-<slug>/`：**假设 → 做法 → 结论 → 改变了哪一个取舍**。
**没改变取舍的实验，不值得跑第二个。**

本轮不新建技术实验。已有服务端命令、HTTP 边界和浏览器 E2E 足以判断“能力在不在”；真正未验证的是运营人员能否按任务顺利完成三条路径，这应作为下一轮的有界人工走查，并记录原始步骤、阻塞点和回读结果。
