## 范围与停止线

本轮修复刚完成的小程序逐页冒烟发现的三类回归：微信 API 合法域名与运行时错误文案、健康
档案记录行窄屏布局、我的页设置入口行为；同时补充源码回归和真实 DevTools 检查。没有修改
医学规则、truth、服务端接口或真实患者数据，也没有把模拟器结果扩大为真机、客户验收或上线
结论。由于客户合法 HTTPS 域名尚未提供，网络能力采用显式安全降级，不伪装成线上内容已恢复。

停止线是：不为一次 CSS 几何问题引入仓库运行时依赖；测试自动化复用本机已存在的微信开发者
工具与 `miniprogram-automator`，不把该工具写入生产依赖。源码检查证明结构和配置约束，健康
档案的实际宽度、换行和点击可用性由微信开发者工具在 390px 视口复核。

## 实验假设与变量

假设：现有构建后的 Node 检查入口可以稳定捕获 #378 的配置与错误暴露、#380 的无行为入口，

## 回归用例与检查点

入口：`cd src && npm run test:smoke:miniprogram`。每项都带 Issue 编号并单独输出；任一项失败
都退出非 0。

1. `#378/API`：启用患者端网络能力时，`apiBaseUrl` 必须是 HTTPS 域名，不能是 IPv4 地址；
   未配置合法域名时必须关闭网络能力、登录和问助手，并在请求层返回 `network_unavailable`，不
   调用 `wx.request`。
2. `#378/文案`：问助手和学一学沿用统一错误转换，患者不可看到 `request:fail`、`url not in domain list` 或 `errMsg` 等微信运行时细节。
3. `#379/结构`：健康档案记录行必须声明可证明的窄屏兜底（行内换行并约束操作组、媒体规则，
   或等价的可收缩 grid/flex 方案）；真实 390px 视口还要测量按钮几何。
4. `#380/行为`：我的页所有带箭头的 `profile-item` 都必须绑定 `bindtap`/`catchtap`，并由现有小程序清单门禁确认处理函数存在。

## 真实 DevTools 手工检查点

源码门禁通过后，才在微信开发者工具中复核以下实效标准：

1. 视口固定为 iPhone 模拟器 390px；进入“我的”→“健康档案”，授权后各保存一条暴露和用药记录。
2. 两类记录的标题、正文在一行或合理换行显示，不出现逐字竖排；“编辑”“删除”按钮均完整落在视口内，右边界不超过内容卡片。
3. 回到“我的”，点击“隐私与授权”和“关于抗敏先锋”，每个入口都有可观察的页面、弹层或明确提示行为；没有点击无反应的假入口。
4. 进入“问助手”和“学一学”，网络失败时只显示患者可懂的失败提示，不显示微信平台原始错误。
5. 截图至少保留：健康档案记录行、我的页两个设置入口、问助手/学一学错误态；截图只使用模拟或匿名数据。

## 结论与限制

源码级门禁与真实 DevTools 几何门是两层证据，不能互相替代。当前 #378 通过安全降级解决的是
“把不可用网络入口暴露给患者”的缺陷，不等于客户合法域名已经登记、文章视频或问助手已经在线；
后续正式联调仍需客户提供合法 HTTPS 域名并在微信后台完成配置。PostgreSQL、S3/MinIO、真实
微信身份、真机和客户验收仍不在本轮证据范围内。
