# 管理后台独立与患者 Web 退役有界实验

- 日期：2026-08-27
- 状态：通过
- 基线：`origin/main@628b55f`
- 对应 Issue：#345

## 假设与边界

把浏览器工程收敛为一个 `apps/kangmin-admin/{src,tests}` 小壳，并删除作者确认废弃的患者 Web，可以降低典型后台变更的导航歧义，同时保持管理功能和小程序能力不退化。本实验不改业务服务、数据库、医学规则、truth、权限模型或生产数据。

放行标准：后台包可独立 build/typecheck/test；`/` 与既有 `/admin` 复用同一个后台入口文件；真实浏览器以真实数据库和 HTTP 会话完成登录、文章保存发布、四个模块导航及两种视口检查；管理 HTTP 与小程序窄测、根完整门禁均通过。

## 结果

- 旧患者 Web、其专用资源和交叉缠绕的患者浏览器脚本退役；后台 E2E 保留真实数据库、HTTP、HttpOnly Cookie、文章保存发布、移动/桌面视口和导航。
- 管理后台分页纯函数移入自己的测试区，患者小程序不再把旧 Web 当视觉正本，改为直接锁定自身患者文案、比例和资产格式。
- 代码文件数 319→306；超 600 行绝对数 45→44，但因分母缩小，占比 14.1%→14.4%，不能把占比上升误判为新增长文件。
- 用例密度 6.0→6.3，导航成本 13.62→13.61；p50 120→121。两条线并非全面同向，只能判为清掉废弃实现并收紧入口，不外推为整体重构已经完成。

## 成本与限制

候选净删除约七千行，其中多数是已退役患者 Web 及其专用 E2E。患者界面的真实端到端验收应在微信开发者工具和真机完成；当前 CI 仍只能以小程序逻辑测试、服务端契约和结构检查承接，不能冒充微信真机验收。
