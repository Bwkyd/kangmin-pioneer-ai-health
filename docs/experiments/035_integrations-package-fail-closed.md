# 外部适配器包失败关闭有界实验

- 日期：2026-08-27

- 基线：`origin/main@069bb1a`
- 对应 Issue：#348

## 假设与边界

把既有 AI、对象存储、身份、安全、环境、临床和运维适配器收进 `@kangmin/integrations`，可以让外部系统变更停在一个包内。本轮只移动实现、改写导入和补结构门禁，不改提示词、端口、错误映射、超时、业务规则、SQL、truth、医学规则或生产数据。

执行前放行标准：集成包独立 typecheck/build；最多七个明确能力目录；只依赖 core、Node 与包内声明的 AWS SDK；旧 `infrastructure/` 零残留；未配置、超时、非法端点和上游错误继续失败关闭；适配器窄测、四组冒烟、完整门禁和真实浏览器 E2E 通过。

## 结果

- 包内固定为 `ai / storage / identity / security / environment / clinical / operations` 七个能力目录，12 个适配器均为路径迁移。
- 先写 `check-integrations-package.mjs`，旧结构如期非零失败；迁移后它检查统一小壳、依赖归属、禁止反向依赖和旧目录零残留。
- 拆空旧目录后，数据库护栏暴露“旧目录必然存在”的假设；已改为目录存在时才检查残留，最终结构可通过。
- AI、加密、本地/S3 存储、远程调用、配置与环境窄测 75 项中 67 通过、8 项因本机未配置 S3 跳过。四组冒烟 2/2、2/2、3/3、6/6；完整本地门禁 358 通过、78 条外部资源测试跳过、0 失败，后台 2 条与真实 Chromium E2E 通过。

## 成本与限制

包边界增加一个 manifest、README、测试说明和机械门禁，运行时镜像必须同步携带 workspace manifest/dist；Dockerfile 已补齐这两个阶段。真实 S3 契约和 OCI 包装以 PR CI 为最终放行条件，不能把本机跳过算通过。
