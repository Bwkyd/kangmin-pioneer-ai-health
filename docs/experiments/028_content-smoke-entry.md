## 假设与范围

假设：把账本中已经存在的两条高信号测试按测试名逐条编排，就能以低维护成本确认
“登记→索引→启用→患者问答→停用”和“启用参与语义检索、停用被排除”，不需要复制
fixture 或新增业务实现。

本实验只涉及四个实体：内容供给闭环、快速冒烟入口、选择器失败护栏、交付记录。
不修改知识状态机、检索实现、truth、数据库迁移、患者数据或临床规则。

## 实现与变量

- 新增 `src/scripts/run-content-smoke.mjs`，对 `admin-agent.test.js` 和
  `semantic-knowledge-retrieval.test.js` 分别启动独立 Node 测试进程。
- 每次使用逐字精确的 `--test-name-pattern`，回读 TAP 中唯一实际执行的非跳过测试；
  零命中、部分命中、测试进程失败均退出非 0。
- 新增 `npm run test:smoke:content`，先构建再调用上述编排器。
- 未新增 fixture；目标断言仍由原测试文件持有。

## 证据

测量环境为 macOS、Node `22.23.1`、最新代码基线：

| 检验 | 结果 |
| --- | --- |
| `npm run test:smoke:content` | 2/2 目标实际执行并通过；含构建实测约 3.62 s |
| 故意把第一个目标名改为不存在的名称 | 编排器 exit 1；第二条仍通过，但未被部分命中掩盖 |
| 故意把启用断言改坏 | 目标子进程与编排器均 exit 1；恢复生成产物后正向入口再次通过 |
| 目标测试单独运行 | 两条均 exit 0，分别为 1/1 |
| `cd src && npm run check` | 通过；Node 22.23.1 下 438 项中 360 通过、78 项按环境跳过、0 失败，真实 Chromium E2E PASS |

## 结论与限制

结论：单入口可以稳定证明两条内容行为真的被执行，且能拦截测试名漂移导致的空跑；
运行时间明显小于完整门禁，符合 #333 的最小交付方向。

限制：本地未配置 PostgreSQL、S3/MinIO，因此本实验不替代 CI 的双后端契约；真实
微信身份、客户验收和正式生产就绪也不由该命令证明。Node TAP 的零命中输出会出现
文件级 `ok` 行，编排器将其视为非目标并拒绝通过，而不是把它当成测试命中。
