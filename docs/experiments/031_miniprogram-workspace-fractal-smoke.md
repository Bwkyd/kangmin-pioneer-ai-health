# 小程序 workspace 最小分形样本

- 状态：通过可行性门，保留指标观察
- 日期：2026-08-27
- 基线：`origin/main@783cb74`
- Issue：#344

## 假设与边界

把低耦合小程序迁入 `apps/kangmin-miniprogram`，并为 workspace 建立统一小壳与依赖门禁，
可以先验证 `apps/packages` 结构而不改变患者行为。本实验只移动小程序、路径与检查入口，
不改 AppID、API、问卷、医学规则、患者数据或 Web。

## 检验标准

1. 缺 manifest、非法内部依赖、跨 workspace 相对导入、空壳包、未登记旧目录均被拦截；
   真实 CLI 对违规 fixture 返回非零。
2. 小程序自检、四组 smoke、完整 `npm run check` 与浏览器 E2E 通过。
3. 测试用例密度不下降，长文件基线只迁路径不扩大。
4. 同时记录导航成本；不把目录更整齐直接写成复杂度已经下降。

## 证据

- workspace 自测覆盖 5 类负例，违规 fixture 的真实 CLI 退出非零；
- 四组 smoke 分别执行 2、2、3、6 条高信号行为；
- 完整门禁 438 项中 360 通过、78 项因本机未配置 PostgreSQL/S3 按约定跳过、0 失败，
  真实浏览器 E2E 通过；生产依赖审计为 0；
- 最新主线重算基线为 319 个代码文件、导航成本 13.45、用例密度 6.0；候选仍为
  319 个代码文件、导航成本 13.62、用例密度 6.0，超 600 行占比 14.1% 不变。

## 结论与限制

样本证明 workspace 小壳、微信工程 `miniprogramRoot: src/` 与现有构建可以共存，且行为未退化。
导航成本代理上升 0.17，主要来自 package 小壳增加的层级选择，因此本轮不宣称复杂度已经下降；
保留它的依据是新增了可执行的依赖方向和旧目录收缩约束。后续必须用顶层目录收缩、典型变更
理解范围和最终复诊证明总体收益；若只增加层级而没有缩小理解范围，应停止继续造壳。
