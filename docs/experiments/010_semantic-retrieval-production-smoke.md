# 语义检索生产实现冒烟与有界实验

- 日期：2026-08-22
- 状态：已完成，放行 #236 实现与受控部署
- 代码基线：`codex/issue-236-semantic-retrieval@0f9651a`
- 范围：只验证全部 `enabled` 知识的语义检索、索引存储和上线次序；不验证 #237 的按需搜索路由，也不改变证型、分期或方案规则。

## 假设与变量

1. `text-embedding-v4` 能让既有 10 条同义问法达到 Hit@3 ≥ 9/10。
2. 对当前小语料，应用内精确余弦足够，不需要引入 pgvector 或新的运行时服务。
3. 二进制归一化 Float32 向量比 JSON 更适合 SQLite/PostgreSQL 双存储。

固定既有 142 个脱敏知识切块，只改变向量编码与检索实现；提示注入样本仅用于证明相似度不能承担授权。

## 证据与结果

- 实际调用 DashScope `text-embedding-v4`：HTTP 200，2 个 1024 维向量，约 341 ms、15 tokens。
- 142 × 1024 的归一化 Float32 BLOB 为 581,632 bytes；同组 JSON 为 3,079,711 bytes。
- 应用内精确余弦 1000 次搜索总计约 281 ms，均值约 0.281 ms。
- 用真实向量回放新 SQLite 适配器：10/10 Hit@3，10/10 Top-3 与实验排序完全一致。
- 最终实现对 `enabled` 使用单一检索集；`category` 只随结果返回，不参与用途授权。

## 成本、限制与上线条件

实验只消耗少量 embedding 请求；未增加数据库扩展或常驻服务。当前语料规模适合精确搜索，规模增长后需重新量测，不能把本结果外推到大规模语料。相似度不判断是否应搜索、是否可信或是否允许形成医学动作。

旧数据必须在切流量前显式回填当前模型向量。部署需先备份数据库，在候选 release 上迁移并运行 `reindex-knowledge`，成功后再切换；回滚旧版本时同时恢复迁移前数据库。
