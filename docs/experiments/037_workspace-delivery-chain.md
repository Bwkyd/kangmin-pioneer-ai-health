- 日期：2026-08-27
- 状态：本地验证通过；真实 PostgreSQL/S3/OCI 与生产发布待完成
- 基线：`origin/main@94ee1ce`
- 对应 Issue：#350

## 假设与边界

六轮迁移完成后，只有同时删除临时白名单、精确锁定最终结构、清除所有 workspace 的陈旧产物，并让构建、CI、Docker 使用新入口，才能把“目录整理”变成可持续协议。本轮只收紧门禁与交付链，不改业务实现、SQL、迁移、truth、医学规则、患者数据或界面行为。

执行前标准：`src` 顶层精确为 `apps/packages/scripts/tests`；八个 workspace 具有同一小壳；迁移白名单不存在；旧编译入口无法进入 package/CI/Docker；干净构建不保留任一 workspace 陈旧文件；四组冒烟、完整回归、真实浏览器、生产依赖审计与 SBOM 通过。真实 PostgreSQL、S3、OCI 必须由 PR CI 补齐；部署必须先候选演练和备份，失败可回滚。

## 正负实验结果

- 在删除白名单前先运行最终检查，按预期以非零退出拒绝；删除后恢复通过。
- 在 `packages/kangmin-runtime/dist` 故意放入陈旧标记，根构建先清除所有 `apps/*/dist`、`packages/*/dist` 与根 `dist`，标记未残留。
- 暂存第五个 `src` 顶层目录时，最终 workspace 检查以非零退出并给出实际目录；通用演化护栏按自身口径不拦业务协议，说明二者不能互相替代。
- 再把临时目录扩为 8 个子目录，通用演化护栏以非零退出拦下宽度 8 > 7。所有探针已撤销，正向两道门禁恢复通过。
- 四组冒烟为 2/2、2/2、3/3、6/6；`src` 完整回归 358 通过、78 条因本机未配置 PostgreSQL/S3 跳过、后台 2 条通过，真实 Chromium E2E 通过；`legacy` 127/127 通过。
- 生产依赖审计为 0 漏洞，SBOM 成功生成且保持忽略；本机没有 Docker 命令，未冒充 OCI 已验证。
- 隔离 worktree 缺少被忽略的私密 vault；首次临时链接脚本误用 zsh 特殊变量 `path`，导致同一进程的 `PATH` 被清空且命令未执行。改为任务专用变量后，只读链接三个正本目录，结构检查通过；链接和空容器随即删除。以后自动化脚本不得用 `path`、`home` 等 shell 特殊/系统变量承载循环值。

## 两条演化线

`aias-meta-evolve` 在 17:40 重算 307 个代码文件：用例密度 6.3 个/千行、导航成本 14.23 bit/文件、代码文件中位数 121 行、超 600 行占比 14.4%，与上一观测点全部持平。结果只证明最终护栏没有靠增删小文件改变读数；顶层协议已经收口，但长文件债务没有被本轮解决。

## 成本、限制与停止线

最终检查增加一次秒级 lint，干净构建会删除八个 workspace 的旧产物，避免增量残留但不追求最快构建。通用演化护栏与业务结构门禁的口径不同是刻意分工：前者管跨仓宽度/长度，后者管 `src` 精确协议。

PR 的 PostgreSQL、MinIO/S3、OCI、容器 CLI、审计与 SBOM 任一失败都停止合并。部署候选进程若不能以 `apps/kangmin-api/dist/server.js` 启动、SQLite 副本不健康或网页探活失败，不切换生产；正式切换失败则恢复旧 release 与旧 systemd 入口。`/ready` 的既有加密配置 503 单独记录，不伪装成此次回归。
