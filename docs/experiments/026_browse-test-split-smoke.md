# 浏览测试按行为轴拆分冒烟实验

- 状态：已停止（H1、H2 通过，H3 未通过；候选拆分已撤销）
- 日期：2026-08-27
- 基线：`main@6704705`，GitHub Issue #321

## 目标与边界

用 `src/tests/browse-increments.test.ts` 作为第一个低风险样本，验证“按真实行为轴拆分”能否在
不改生产代码、不删测试、不复制 fixture 的前提下，让失败范围更容易定位。实验只移动测试与
测试夹具，不改变浏览、方案、环境、权限、医学规则、数据库结构或患者可见结果。

## 基线冒烟

- 原文件 610 行，包含 12 个测试。
- `npm run build --silent && node --test dist/tests/browse-increments.test.js` 通过：12/12，
  0 失败，测试进程约 0.37 秒。
- 自然行为轴为：内容与方案浏览、环境数据、跨域访问与存储失败；共享数据库种子和结果断言
  仍应只有一个来源。

## 假设与变量

- H1：拆分后仍能识别原 12 个测试名称，12/12 通过，关键断言不减少。
- H2：每个测试文件只对应一个可从文件名判断的行为域，且全部低于 600 行。
- H3：共享 fixture 只有一个来源；代码文件增加后，导航成本与 p90 不恶化，超 600 行绝对数量
  至少减少 1。

唯一变量是测试文件的物理边界：把原文件拆为内容/方案、环境、访问/失败三个测试文件，并抽取
一份共享 fixture。生产实现、测试数据、断言、测试名称和运行命令保持不变。

## 停止线

出现以下任一情况即停止并撤销实验：测试名称或数量减少；需要修改生产代码；共享 fixture 出现
第二来源；单个新文件仍超过 600 行；完整门禁失败；导航成本或 p90 因拆分恶化。

## 成本、证据与限制

实验预算为一个测试文件、一次窄测和一次完整门禁，不扩大到 #321 的账户或模型端口测试。
证据来自 Node 真实测试进程、项目完整门禁和演化账单。该实验只能证明测试组织方式可行，不能
外推为生产服务、数据库或临床规则拆分已经安全。

## 结果

- H1 通过：候选拆分仍识别原 12 个测试名称，窄测 12/12 通过；首次 typecheck 发现移动时
  漏带三个临时目录 import，恢复后通过，证明编译门禁能在生产代码执行前拦截机械搬迁错误。
- H2 通过：候选形成内容/方案 292 行、环境 190 行、访问/失败 57 行和共享 fixture 116 行；
  测试名称、断言与 fixture 权威来源均未减少。完整 `npm run check` 退出 0，Node 全量回归和
  真实浏览器 E2E 均通过。
- H3 未通过：候选把超 600 行文件从 45 降到 44、占比从 14.2% 降到 13.7%，p50 从 120
  降到 119；但导航成本从 13.45 升到 13.46 bit/文件。用例密度保持 6.0，p90 保持 784，
  TypeScript 字面冗余率保持 38.6%。

按停止线撤销候选测试文件和基线收紧，生产代码从始至终未改。撤销后门禁重新通过，当前指标
回到导航成本 13.45、p50 120、超硬上限占比 14.2%。

## 结论

不放行这次拆分。对仅超上限 10 行、行为仍高度内聚的测试文件，拆成三个测试入口和一个共享
fixture 会用更多导航选择换取更好看的行数；这属于代理指标优化，不是已证明的复杂度下降。
`browse-increments.test.ts` 暂不作为 #321 的优先切片，后续只有在内容、环境或访问失败场景出现
独立高频变化，或能用更少物理入口形成边界时再复诊。本结论来自一个样本，不外推为所有测试
文件都不应拆分。
