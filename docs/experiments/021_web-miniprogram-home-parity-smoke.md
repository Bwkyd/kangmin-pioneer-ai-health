# Web 与小程序首页同构冒烟实验

- 状态：已完成两轮；首页样本通过代码、编译与交互门禁，全站仍未放行
- 日期：2026-08-23
- 代码基线：`main@d1585db`
- 实验对象：仅患者 Web 首页与原生小程序首页；不扩展到助手、记录、内容或我的页

## 假设、变量与停止线

作者确认：除微信平台强制差异外，小程序患者端必须与现有 Web 患者端在视觉、内容、功能、
流程和状态反馈上保持一致。本实验只检验一个最低成本假设：现有小程序首页是否已可作为
逐页同构迁移的合格样本。

- 固定基准：`src/web/src/App.tsx` 与 `src/web/src/styles.css` 的患者 Web 首页。
- 实验变量：`src/miniprogram/pages/home/` 的 WXML、WXSS、JS 和共享自定义底栏。
- 允许差异：微信胶囊、安全区、授权弹窗、键盘、视频原生组件与返回手势。
- 通过线：首页结构、可见文案、入口语义、信息顺序、主要视觉资产和状态表达全部对应；
  平台强制差异必须逐项登记，不能用“原生重设计”解释。
- 停止线：首页不通过时停止扩大到全站，不先批量重写其他页面。

## 冒烟证据

- 公网 `https://140.143.120.176/`、`/admin` 和 `/live` 分别返回 200、200、`status=ok`。
- `npm run check` 中类型、架构、小程序清单、构建和 409 项 Node 测试完成：333 通过、
  76 项因未配置 PostgreSQL/S3 按约定跳过、0 失败。
- 完整门禁第一次在真实 Web E2E 启动前停止：本机缺少 Playwright Chromium 缓存。确认

  患者与管理全链路 `PASS`；随后用同一路径重跑完整 `npm run check`，退出码 0。
- 会话内 Browser 实例不可用，因此本轮没有交互式目测截图；代码与自动化证据不能冒充
  微信真机视觉验收。

## 结论与限制

事实结论：当前小程序首页与 Web 首页的主要信息架构、文案、入口和视觉资产均不同；“底栏
一致、色彩相近”不能支撑“一模一样”。首页样本未达到放行线，因此本轮停止扩展到其他页面。

下一实验应只改首页：把 Web 的横幅、双主模块、依据卡、今日任务、趋势、推荐内容和状态顺序
逐项转换为原生组件；保留小程序请求层、微信身份和原生安全区。首页在开发者工具截图对照、
交互路径和失败态全部通过后，再把同一方法推广到问助手。真实 AppID、微信登录、合法域名与
真机仍是外部限制；本实验不证明客户验收、微信审核或生产就绪。

## 第二轮有界实现与复核

第二轮仍只改首页样本，没有扩大到其他患者页面：小程序复用 Web 同一品牌横幅、双主模块、
依据卡、今日任务、真实/占位趋势和固定推荐入口；尺寸、间距、圆角、阴影和插画色按当前
Web CSS 的 `px → 2rpx` 比例转换。首页只读取记录概览，不再额外拉取动态文章与视频；
“过敏原记录”进入健康档案中的暴露表单，“学一学”“诊一诊”和趋势分别进入现有原生路径。

- 品牌图片与 Web 文件逐字节一致；自动化逐项比对 14 条可见文案，并拒绝三条旧版分叉文案。
- 小程序窄测 17/17；完整门禁 412 项测试中 336 通过、76 项因未配置 PostgreSQL/S3 跳过、
  0 失败，真实 Chrome 患者与管理端 E2E 通过。
- 微信开发者工具 RC 2.02.2608031 在临时 AppID 副本中真实编译：首页 WXML 树完整挂载，
  控制台 0 错误；点击“过敏原记录”到达 `pages/health-profile/index`。首次基础库脚本 500
  经清理编译/网络缓存后消失，属于工具缓存而非应用错误。
- 官方 `miniprogram-automator@0.12.1` 与当前 2026 RC 工具协议不兼容：先在版本比较处读到
  未定义值，绕过后又超时。因此没有把失败的 SDK 自动化冒充 E2E 通过，也没有真机截图。

首页样本现在可进入 PR 与微信开发版上传；“患者端全站与 Web 一模一样”仍需按同一判据逐页
推进。微信登录、合法域名、真机视觉与微信审核仍是外部验收，不由本轮自动化替代。
