## 问题与停止线

本实验只裁决两个实现分叉：

1. “更新文件”是新建另一条知识记录，还是保留知识 ID 并原子替换源素材、正文分块与索引；
2. 未启用资料的检索测试是临时加入全库，还是只在明确 knowledge ID 的隔离查询中读取。

停止线：证明更新失败时旧记录及患者检索状态不变；更新成功后旧启用状态不沿用；单资料
测试可以命中未启用资料，同时患者全库检索仍不能命中。实验不改问卷、临床规则、目录语义
或全库检索的 enabled 门禁。

## 假设与变量

- H1：保留知识 ID、在一个仓储事务内替换文件元数据、分块并删除旧向量，可以避免半更新，
  也能让既有目录与运营链接稳定。
- H2：新素材必须先完成现有上传校验；替换事务失败时只留下可管理的独立素材，不改变旧知识。
- H3：检索端口增加显式单知识查询，比临时改状态更安全；它不会把未启用资料暴露给患者链路。
- 对照方案：新建知识记录再删除旧记录。它会改变 ID、目录引用和列表身份，且两个记录切换
  需要额外版本关系，因此不作为首选。

## 证据与验证

- 现状窄测：知识服务、上传、目录迁移、重建索引与语义检索共 31/31 通过。
- 现状真实浏览器冒烟：患者与管理端全链路 PASS。
- 将增加失败注入测试：不存在/未就绪素材、解析失败、仓储事务失败、更新已启用资料、
  单资料命中与患者全库排除。
- 将同步验证 SQLite 与 PostgreSQL 仓储契约，避免只在试用数据库成立。

## 预期成本与限制

- 成本：一个仓储原子替换方法、一个显式单资料检索端口、服务/API 窄测和双端真实 E2E；
  不新增迁移，因为现有知识与素材表已包含所需字段。
- 更新成功后资料进入 `processing` 或 `index_failed`，必须重新索引、测试并由运营明确启用；
  这是可用性换安全性的确定性取舍。
- 新文件上传已完成而替换事务失败时，素材行与对象仍可在后续文件管理中处理；不删除人手上传
  的原件。本实验不承诺自动垃圾回收。

## 结论

- H1 通过：SQLite 服务测试证明启用资料换文件后保留知识 ID、重置为未启用并替换分块；
  PostgreSQL 契约测试验证旧向量清空、分块替换和陈旧版本拒绝。
- H2 通过：素材不存在时旧启用知识及患者全库命中保持不变；解析失败提交为同一条
  `index_failed` 安全状态，不出现新旧两条知识或半更新。
- H3 通过：单资料查询可命中 `indexed`/`disabled` 资料，但患者全库仍只读取 `enabled`。
- 首轮评审另发现全库命中状态可能串入新增/换文件任务；已在两个任务边界清空查询与命中，
  并用真实浏览器先制造全库命中后验证“明确启用”仍禁用。
