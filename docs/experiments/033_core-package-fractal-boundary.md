# 核心包四组边界有界实验

- 日期：2026-08-27

- 基线：`origin/main@2068478`
- 对应 Issue：#346

## 假设与边界

把纯内核、领域端口、领域服务和纯应用编排迁入私有 workspace 包 `@kangmin/core`，并按 `patient / intelligence / content / operations` 四组归位，可以让后续数据库、外部集成和运行入口只依赖稳定核心边界。本轮只移动职责和改写导入，不改数据库 schema、HTTP/CLI 协议、界面、truth、医学规则或患者数据。

执行前放行标准：核心包必须独立 typecheck；不得依赖 infrastructure、HTTP、CLI、apps、数据库或外部集成实现；旧 `kernel/`、`modules/` 必须消失；四组冒烟、医学规则稳定哈希、完整门禁和真实浏览器 E2E 均通过；演化护栏必须完成正反验证。

## 结果

- 核心包形成 `kernel + 四组`：患者应用编排归 patient，管理应用编排归 operations，没有再制造无业务含义的 `domains/` 或 `application/` 壳层。
- 外围代码统一经 `@kangmin/core/*` 导出访问；生成问卷脚本也不再读取已退役的 `dist/modules/*`。
- 核心包独立 typecheck、架构门禁和构建通过；四组冒烟分别为 2/2、2/2、3/3、6/6，医学规则与医学发布门禁 36/36。
- 完整本地门禁为 360 条通过、78 条因未配置 PostgreSQL/S3 如实跳过、0 失败，真实 Chromium 后台链路通过。
- 冒烟实验捕获了一个旧测试名漂移导致的空测试假绿，已把 shell 目标更新为当前真实名称并再次 6/6 通过。
- 首次 PR 的 `quality` 通过、OCI image 失败，暴露 Docker 缓存层没有先复制 workspace manifests，且运行层没有保留 core 包目标；修复后容器构建链也按真实 workspace 边界装配。

## 复杂度账与限制

代码文件数、p50、超 600 行占比和用例密度保持 306、121、14.4%、6.3；本轮不拆存量长文件，也不把移动冒充拆分。导航成本从基线 13.60 升至暂存候选 13.89 bit/文件，主要来自新增 workspace 包边界、manifest、检查脚本和包内路径。曾试验并删除 `domains/` 空壳，但无法抵消包边界成本。

因此本轮只能证明“典型依赖范围变得可机械约束、旧行为未变”，不能宣称全仓导航复杂度已经下降。#347–#349 继续把 database、integrations、runtime 从 `src` 散目录收进同构包，#350 才按最终树复诊总导航成本；若最终仍不降，必须调整结构，而不是扩大豁免。
