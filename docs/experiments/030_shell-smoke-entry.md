## 范围与停止线

本轮只处理一个实体：次要·基础壳。目标是把已有会话、导航、传输和环境门禁断言编排
为单一、快速、不会空跑的入口，不改小程序运行时、登录协议、服务端配置、数据库 schema、
truth、医学规则或患者数据。

不复制 fixture，不把真实微信身份、真机、PostgreSQL/S3 契约或客户验收伪装成本地冒烟，
不按行数拆测试文件。若正向不能 6/6，或任一失败注入不能稳定 exit 1，则停止交付并回退。

## 执行前检验标准

入口必须逐条唯一命中以下既有测试：

1. 小程序公共请求免登录，患者记录通过 `wx.login` 换取 Bearer 会话；
2. 患者命令遇到 401 时清理旧令牌，并且只重登重试一次；
3. 微信登录未配置时安全拒绝，且不发出身份请求；
4. 小程序首页只读取记录概览，并保持与 Web 一致的四条入口；
5. 小程序流式请求按 NDJSON 增量输出，正确还原跨 chunk 的中文 UTF-8；
6. production 与未设置 `APP_ENV` 且未显式开发降级时均 fail-closed。

每个目标独立启动 Node 测试进程，TAP 中必须有唯一、逐字匹配的非跳过 `ok`。目标名
漂移、零/部分命中、`# SKIP`、`# TODO`、断言失败、进程启动失败都必须退出非 0。

## 假设与变量

假设：复用上述六条断言即可覆盖基础壳的会话、失败、导航、流式和环境不变量；变量只有
测试筛选方式和故意失败输入，不引入新的业务变量或共享夹具。
