## 目标与四实体边界

验证 `src/tests/model-ports.test.ts` 能否只按两个既有变化轴拆分：模型适配/降级，以及确定性
输出校验/模板。只移动测试和各自 helper，不修改生产代码、模型调用逻辑、临床规则、患者文案、
数据库或外部环境。本轮总共只处理测试套件、实验校验、演化基线、交付链四个实体。

## 拆分前不变量与检验标准

1. 原文件共 26 个 `test(...)`：适配/降级 16 个，输出校验/模板 10 个；拆分后测试名称集合必须
   与 `HEAD:src/tests/model-ports.test.ts` 逐字一致，数量仍为 26。
2. 只允许生成 `model-adapters.test.ts` 与 `model-output-validation.test.ts` 两个测试入口；共享
   fixture 必须保持唯一正本，不修改 `src/` 下任何生产文件。
3. 两个候选文件均不得超过 600 行；旧 `model-ports.test.ts` 删除后，演化基线必须同步收紧。
4. 基线窄测、候选窄测、`cd src && npm run check`、`cd legacy && npm run check` 均须退出 0；
   真实浏览器 E2E 必须执行，不以 typecheck 或单测代替。
5. 演化复诊必须满足：超 600 行绝对数量至少减少 1；用例密度不降；p90 与导航成本均不恶化；
   门禁先能指出旧基线可移除，收紧后再通过。
6. 医学安全测试名称与断言必须保留：急症前置分流、未知药量前置分流、方案外穴位/数值拒绝、
   规则结果不一致拒绝、candidate 阻断、固定 system notice 不携带模型文本。

## 自动执行方式

- 用 `comm -3` 对比拆分前后排序后的测试名称集合，任何输出都视为失败。
- 用 `git diff --name-only` 断言代码改动只落在两个候选测试文件和旧文件删除。
- 用 `wc -l`、项目演化护栏和 `aias-meta-evolve` 检查文件上限与两条趋势。
- 完整门禁后执行 `$km-review`；再按作者要求调用 sequential-thinking 做元反思，重点寻找
  import 遗漏、测试发现变化、helper 复制、医学负例丢失以及“行数下降但导航成本上升”的变式。

## 停止线

测试名称或断言减少、需要修改生产代码、出现第三个测试入口或共享 fixture、完整门禁失败、真实
外部依赖被错误跳过、导航成本或 p90 上升，任一发生即撤销候选；不得为了通过代理指标放宽标准。

## 结果

第一候选把原入口拆为 472/340 行两个测试文件；26 个测试名称、医学安全不变量、窄测、完整
`src`/`legacy` 门禁与真实浏览器 E2E 均通过，导航成本 13.45 不变，超限占比 14.2%→13.8%。
但它复制了两个裁决 helper，回读 #321 原始验收后确认违反“共享 fixture 保持单一来源”，未放行。

第二候选抽出 40 行唯一 fixture，两个测试入口降为 430/302 行，总测试代码仅比原文件多 6 行，
窄测 26/26 与护栏通过；但新增第三个代码文件使导航成本 13.45→13.46，触发停止线。仓内没有
职责匹配的既有 fixture；把模型裁决塞入内容或 consent fixture 会制造错误归属。因此全部源码与
基线改动已撤销，指标恢复 13.45 / 14.2%，生产代码始终未改。结论：在“单一正本 + 导航成本
不升”的当前约束下，`model-ports.test.ts` 尚不能安全拆；需等既有公共测试支持层出现，或作者
明确接受 +0.01 导航成本这一取舍后再开新实验。
