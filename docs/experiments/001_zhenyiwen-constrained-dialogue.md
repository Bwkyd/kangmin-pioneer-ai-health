## 做法

1. **转换**：python-docx 批量把手册 docx 转 md（正文+表格，图片导出到 assets），
   产物进 `_work/20260813-shiyi-shouce-inspect/`（忽略区，客户材料不入仓）。
2. **切块**：按章/节切块，标注穴位/疗法/禁忌标签；与现有知识库分块结构
   （knowledgeId+chunkIndex）对齐，便于实验后直接入库。
3. **原型**：对照 `src/infrastructure/deepseek-model-adapter.ts` 写千问适配器脚手架
   （DashScope OpenAI 兼容模式）；原型脚本走「参数组装 → Prompt → 生成 → 追问回合」，
   每轮输出做白名单断言（名单外穴位/疗法零出现）。
4. **视觉**：手册导出图片抽样送千问 VL，评估识别质量与转文字条目的可行性。

## 发现（证据可复现于 `_work/20260813-shiyi-shouce-inspect/`）

- **F1 操作数值编造**：首轮生成出现「每次3–5分钟」「每日1次」类参数未给的数值；提示词加
  示范句（「不得写每次3–5分钟，应写以皮肤微红温热为度」）后消失。**生产层建议**：除提示词
  外加输出校验——数值+单位必须来自参数，否则替换为安全表述或降级（提示词约束是概率性的）。
- **F2 操作方式自补**：参数只给穴位名时，模型自选操作方式（按揉/温敷/擦法/压豆）。**接入
  时诊疗参数必须携带 truth 的操作说明（或视频引用），模型只做语言转译，不自行发明操作**。
- **F3 语料与检索**：手册正文不含「鼻三线」（与 truth 方案互补，入库须两者都进）；朴素
  bigram 检索对患者式提问召回差（目录/动物实验/拔罐块噪声），标签加权有限改善；候选：
  向量检索（qwen3.7-text-embedding 可用）或模型重排——报价外基础设施，待拍板。

## 结论与推断（跑完回填）

- 结论：千问（qwen-plus）在参数白名单约束下可生成通俗方案文本，并能安全应对追问
  （越界疗法拒绝 + 建议咨询医生）；视觉（qwen-vl-plus）可识别手册穴位图。原型 6/6 断言
  通过，可行性成立。
- 推断：可行性不等于生产质量——F1/F2/F3 都要在接入时闭环；qwen3.7 系列为更新候选；
  检索是否升级待作者拍板。推断不写成当前事实。
