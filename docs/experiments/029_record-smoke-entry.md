## 范围与停止线

本轮只处理一个实体：次要·症状管理。目标是把已有高信号测试编排为单一、快速、不会
空跑的入口，不改记录服务、数据库 schema、患者界面、医学规则、truth 或患者数据。

不复制 fixture，不把 PostgreSQL 契约跳过当作通过，不按行数拆测试文件。

## 执行前检验标准

入口必须逐条唯一命中以下既有测试：

1. 日历按日合并症状/暴露/用药，趋势只读且不填充；
2. 解密失败返回 `storage_unavailable`，不伪装空数据；
3. 体验版授权后保存症状，并在日历和“我的”页回显。

每个目标独立启动 Node 测试进程，TAP 中必须有唯一、逐字匹配的非跳过 `ok`。目标名
漂移、零/部分命中、`TODO`、断言失败、进程启动失败都必须退出非 0。

## 假设与变量

假设：直接复用上述三条断言即可覆盖 #334 的保存→回读→日历/趋势及缺失值边界；变量
只有测试筛选方式和故意失败输入，不引入新的业务变量。

测量环境为 macOS、Node 22.23.1；工作树基于 `origin/main@226905d`。

| 检验 | 结果 |
| --- | --- |
| `npm run test:smoke:record` | 3/3 目标唯一命中并通过，含构建约 4 秒 |

## 结论与限制

结论：`test:smoke:record` 已形成单一、快速、失败关闭的症状管理检查点，覆盖按日保存、
回读、月历/趋势投影和缺失值边界；不新增 fixture，不改变生产行为。

限制：PostgreSQL、S3/MinIO 契约仍由 CI 提供真实适配器证据；本入口不代表双后端、真实
微信身份、真机或客户验收。当前候选尚未提交、推送、建 PR、合并、部署或关闭 #334。
