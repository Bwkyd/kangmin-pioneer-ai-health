# 管理后台工作台首屏冒烟实验

- 状态：已完成（H1–H3 通过）
- 日期：2026-08-26
- 基线：`origin/main@3cdba1a`，GitHub Issue #281

## 目标与边界

验证工作台能否在不改变服务端内容状态、发布规则和既有业务页的前提下，收敛为“今日待办 → 快捷新建 → 内容概览”。只改工作台信息架构和入口连接，不改临床规则、接口、数据库或患者端。

## 假设

- H1：移除欢迎横幅、五张等权统计和重复发布说明后，1440×900 可完整看到三个主区块。
- H2：三个快捷入口可以直接打开文章、视频和 AI 知识的新建流程，而不是只进入列表。
- H3：390×844 不横向溢出；既有文章、视频、消息、知识和文件管理闭环不回归。

## 证据与结果

- 改动前：`npm run build` 与 `node scripts/web-browser-e2e.mjs` 均通过，确认旧功能基线有效。
- 改动后浏览器断言：桌面三个区块均位于 900px 视口内；移动端 `scrollWidth <= innerWidth`。
- 三个快捷入口分别真实打开“新增文章”“新增视频”“新增知识”对话框。
- 完整浏览器 E2E 继续覆盖内容编辑、预览、发布/下架、知识索引/启停、文件引用保护并通过。

## 成本与限制

实现与首轮验证约 25 分钟；使用无身份测试数据和本地真实 HTTP 服务。该实验证明实现和回归门禁，不替代客户对信息密度与视觉口味的最终验收，也不把 `/ready` 的既有加密配置缺口视为本轮问题。

## 结论

H1–H3 均通过，放行 #281 的完整检查、评审和交付。
