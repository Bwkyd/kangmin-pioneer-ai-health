## 为什么光有护栏不够

`guard.sh` 只回答**什么活不下来**。全靠它，系统会整整齐齐、一条规矩不破，
**但它不往任何地方长**——不再解决新问题，人绕开它自己干。

护栏防的是散，收敛点管的是往哪长。两个都要有。

---

## 一、收敛点：这个系统收束到哪一点

> 「注意力该放到哪里？放到**收束到哪一点**上……**每个领域不一样**。
> 没有这一点，并行只会让你无限地发散。」

**一句话写下来**（写不出来，说明这一步还没做）：

>

**让过敏性鼻炎患者在不越过医学边界的前提下，获得有依据、听得懂、能执行、可持续的鼻健康管理。**

**系统名 ≠ 收敛方向**：同一套方法换个方向就是另一个系统。

## 二、凭什么被留下

说不出「凭什么留下」，收敛点就还只是一句口号。至少给出一样可执行的：

| | 填 |
|---|---|
| **一份正例**（照着它做就对了的那一个） | 内容分类注册表纵切：服务端稳定 ID 作权威、管理端明确维护、Web/小程序共用、迁移有报告、未决状态 fail-closed，证据见 `docs/changes/ops/015_content-category-registry-deploy.md` |
| **一条验收**（怎么算通过） | 产出必须直接闭合或明确支撑「可信内容 / 安全调理 / 持续管理」之一；相关窄测和 `cd src && npm run check` 通过，患者可见越界医学内容为 0，外部资源跳过项如实报告 |
| **一个排序规则**（两个都能做，先做哪个） | 先 P0/P1 安全或迁移阻断；同级时，先能最小闭合三个闭环之一、且同时缩小典型变更理解范围的任务 |

正例给人看，**负例给脚本查**——负例那一半写进 `guard.sh`，别放在这里。
**风格是通过负例落到规则层的：把判好坏降级成判对错。**

## 三、什么时候淘汰

规矩不淘汰，就会变成**把旧习惯固化**。

| | 填 |
|---|---|
| 这条规矩**什么条件下重新讨论** | 连续两个真实变更被同一护栏误拦，或目录协议/作品边界经作者确认改变时；先调整范围和豁免理由，不默默抬高阈值 |
| 例外的**期限与责任人**（没有期限的例外就是后门） | 2026-08-27 存量宽度/长文件基线：期限 2026-09-30，责任人作者；到期按实际收缩值重建，不自动续期 |
| 哪些东西**该被这一轮淘汰掉** | 新增超 600 行文件、让基线长文件继续变长、让已超宽的目录继续变宽，以及为了压数字而产生的空转发层 |

## 四、让选择压力自己更新

到最后，规矩不再靠你去想，而是系统用自己跑出来的数据把旧的换掉。

盘点这个项目**实际发生过什么**——跑过哪些对话、用过哪些技能、哪些动作高频——
把高频动作固化成命令，**用「测出来的」换掉「猜出来的」**。

> 你以为自己常用什么，和你实际常用什么，**往往差得很远**。

**光看频次不够**：**高频也可能只是历史惯性**——你一直这么干，所以它一直高频。
再加一条效果反馈：**用了它之后，那件事是不是真的更快、更少返工了？**
没有这一问，「自更新」就只是把旧习惯固化。

效果反馈还可以**提前写好**：系统还做不到某项能力时，**先把那条评测写出来——
它定义了这项能力**；新模型一发布，跑一遍，立刻看出哪些赌注押对了
（出处：Anthropic《Demystifying evals for AI agents》，2026）。

| | 填 |
|---|---|
| 为下一档能力预写的那条评测 | 后续任一后台真实变更应主要落在一个命名功能单元，`AdminApp.tsx` 继续只做组合；相关窄测、真实浏览器契约与 `cd src && npm run check` 全绿，且不得以空转发层、循环依赖或扩大豁免换取表面整齐 |

**它只能长在这一步**——初始化时这些数据全是零，跑不起来。
**不是做得过早，是无米之炊。**

## 放行判据

不是「这份表填满了」，是：

1. 收敛点**写成了一句话**，而不是一个名字
2. **「凭什么留下」至少有一样是可执行的**（正例／验收／排序，任选其一）
3. 例外**都带期限和责任人**

**填不出第 2 条，就还停在愿景里。**
