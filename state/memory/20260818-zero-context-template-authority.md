# 零材料模板不得制造隐性授权

## 触发条件

初始化技能承诺零前置材料，却需要生成使用者、日程、资源、真相源、参与者职责或人机分工。

## 做法

- 脚本只填名称、日期、目录等可机械确定的事实。
- 有本地证据或用户原话的事实才能填入；其余明确写“待核实”，不留裸空字段诱导补猜。
- 角色和权限只来自明确授权；不把“AI 负责其余全部”或“人不做规则检查”作为默认分工。
- 未登记职责不构成授权。初始化成功不授权发布、部署、外部发送、敏感数据处理、专业结论或其他高影响动作。
- 用编程、内容、科研、教研等不同领域做零材料前向测试，检查模板是否凭惯例编造事实或权限。

## 边界

领域知识可以用于起草待人确认的方向，但不能据此补写现实事实、真相源地位或权限边界。
模板的安全默认不替代项目更具体的明确授权。

只要同一默认角色句在任一合理领域可被解释为自动发布、部署、处理敏感数据或作出专业结论，
该默认就不具有跨领域安全性。
