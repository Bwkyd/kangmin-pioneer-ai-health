# 患者可见状态保持单一来源

## 模式

对规则裁决做过滤、截断、脱敏或展示映射后，应先生成唯一的“患者可见有效状态”，再由以下出口共同消费：

- 助手正文；
- 前端结构化控件数据；
- 本轮 API 响应；
- 会话持久化与刷新恢复。

不能让正文使用派生状态、控件和持久化仍使用原始状态，否则同一轮会出现相互矛盾的题目或结果。若先截断再过滤，还必须从未过滤全集中补位到展示上限，避免过滤后形成空展示集。

## 验证

状态机回归不能只断言 outcome 或“仍在进行”，至少同时断言：

1. 本轮输入已进入确认事实；
2. 助手正文中的问题与结构化 `nextQuestions` 一致；
3. 下一题相对上一题确实推进；
4. 刷新恢复后的问题和友好答案与实时界面一致；
5. `unknown`、否定、肯定三类分支均覆盖，其中 `unknown` 不误当否定，也不无限重复。

## 恢复时的视图挂载

数据可能在目标页面尚未挂载时完成恢复。依赖 DOM 的副作用（滚动到最新消息、聚焦、
测量尺寸等）不能只监听数据变化，还要监听目标页面/组件进入可见状态；否则刷新后先在
首页恢复数据，再进入聊天页时，副作用不会重跑。E2E 应覆盖“刷新 → 切回目标页面 →
确认最新内容位于可视区域”，不能只断言内容已经存在于 DOM。
