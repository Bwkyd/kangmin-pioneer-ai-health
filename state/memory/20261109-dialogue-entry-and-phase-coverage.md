# 问答验收必须覆盖入口与会话阶段

独立知识问答成功，不能证明主助手的新会话也能回答；评估后追问成功，不能证明问卷前
或问卷中途也具备同样能力。诊断“以前能用”时先对照真实命令、HTTP 路由和状态分支，
再追溯历史提交；同 Key、不同入口的对照能区分模型配置与业务路由缺口。

## 验收矩阵

| 场景 | 必须验证 |
| --- | --- |
| 新会话普通科普 | 正常回答，不强迫问卷，不写患者确认事实 |
| 连续指代追问 | 回答当前问题，并正确使用本会话上下文 |
| 主动开始评估与结构化选项 | 原规则节点和分支保持确定性 |
| 问卷中途科普插问 | 回答后保留原待答节点，继续作答可推进 |
| 完成评估后的追问 | 使用已确认上下文，仍守规则和医学边界 |
| 模型故障与急症混合输入 | 原文保留、失败提示准确；结构化续答独立可用，急症先于事实解析 |

同一案例应交叉验证真实 CLI、HTTP 分片终态、持久化回读与客户端恢复；有副作用的测试
使用隔离库和模拟文本。把本地检查、外部适配器、真机与客户验收分别记录，不能跨层替代。
