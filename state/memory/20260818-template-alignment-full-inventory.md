# 模板对齐必须核对完整生成清单

## 触发条件

已有项目声称采用某个初始化技能或模板，需要检查是否与当前模板对齐。

## 做法

- 先完整读取技能及其初始化脚本，以脚本实际生成的全部文件和目录为清单，不凭摘要猜测。
- 在隔离临时目录使用同等参数生成基线，再逐项核对目标项目。
- 把差异分为：模板结构已由项目事实替换、模板要求但真实缺失、项目已登记的本地特例。
- 保留已演化项目的事实、隐私、命名、医学和 Git 特例；只移植模板机制，不用通用占位覆盖已确认事实。
- 把稳定、可机械判断的核心缺失加入结构检查；私密目录只跟踪边界说明，不放行内部内容。
- 最后执行清单、目录、双入口一致性和技能要求的新会话冒烟。

## 边界

“与模板一致”不等于逐字相同。模板提供职责、结构和默认机制；项目事实必须来自项目证据。
删除、迁移历史材料或改变权威来源仍需单独确认。
