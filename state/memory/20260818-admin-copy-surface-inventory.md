# 管理后台可见文案全量盘点

管理后台的命名调整不能只替换截图指出的导航项。先按页面和状态建立可见表面清单，再逐项核对侧栏分组、页面标题与副标题、眉标、卡片标题与说明、空状态、按钮、状态提示和错误提示；同时检查响应式布局下是否存在另一份可见文案。

## 做法

- 以运营人员能理解的任务语言为准，清除只对内部开发者有意义的范围或交付术语；内部变量、CSS 类名和服务端命令只在真实语义需要时改动。
- 对每个受影响入口增加正向文案断言，并在工作台容器级增加旧内部术语的负向断言；负向断言自身可以保留被禁止词，用来防止回归。
- 响应式场景不要把 CSS `visibility` 当作文案是否存在的唯一判据；需要时直接读取导航或页面 DOM 文本，再用真实交互路径确认用户能到达目标页。
- 文案改动后重新走工作台、文章、视频、站内消息和知识库入口，并确认患者端、后端接口、权限和医学规则没有随之变化。

## 边界

历史状态记录、产品决策和报价 truth 保留其当时的事实与术语，不为追求全文检索零命中而改写历史；当前用户可见界面和回归断言才是本规则的直接对象。
