# 响应式界面必须验证实际几何

修复溢出、缩放、裁切、定位或命中区时，源码中存在 `max-width`、`max-height`、`object-fit`、
`overflow` 等声明，只能证明规则被写入，不能证明浏览器最终布局满足目标。父容器、固有尺寸、
媒体比例、滚动区和视口单位都可能让声明存在但实际几何仍错误。

## 做法

- 至少选择一个窄屏和一个桌面视口，覆盖目标内容的典型极端比例或长度；不要只用单一默认视口。
- 在真实浏览器读取 computed style，并用 bounding box 断言最终宽高、位置和视口边界；媒体同时
  检查 `object-fit`、固有比例和滚动行为，交互控件同时检查视觉盒与命中盒。
- 同一回归同时锁定目标变化和旧功能：正向断言新布局或文案成立，负向断言旧错误消失，并确认
  底层校验、发布、权限、错误提示等未被表面改动误删。
- 断言使用由视口和产品约束推导的数值边界，不仅比较 CSS 文本；否则重命名、打包或规则覆盖都
  可能制造假绿。

## 边界

自动化几何断言证明指定浏览器和视口下的行为，不等于所有设备的人工视觉验收。字体渲染、系统
控件或真机容器存在平台差异时，仍需在目标环境补充目测或真机验证。
