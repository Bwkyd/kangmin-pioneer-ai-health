# 患者内容分类必须显式归属

文章和视频的分类属于患者可见信息架构，不能由标题关键词临时猜测。管理后台创建或编辑内容时，
应从服务端权威注册表选择稳定分类标识；Web、小程序和后台都读取同一份标识与展示名称。

## 做法

- 患者端运行时只按稳定 ID 筛选，不保留标题猜测或旧展示字符串兜底。
- 一次性迁移可以按 truth 中的精确标题映射，但必须生成可复核报告；未命中或冲突的已发布内容
  自动下架，人工选定有效分类后才能恢复，不能跨人群继续展示。
- 后台分类字段使用受控选择，不允许自由输入制造近义分类；发布时对缺失、非法、停用、非叶节点
  和内容类型不符全部失败关闭。
- 单分类或多分类由书面产品规则决定：文章只有面向全部人群的“科普文章”，时间仅排序；视频
  才允许显式关联多个叶节点。
- 分类改名只改展示名称，不改变稳定标识；删除、合并或迁移前核对已发布内容和所有患者入口。
- SQLite 与 PostgreSQL 同步实现迁移、锁和约束；回归覆盖迁移报告、未决下架、多关联、改名、
  编辑后重新发布，以及 Web、小程序和后台按内容 ID 得到一致分类。

## 边界

分类选择不授权新增医学分类、改变内容正文或扩大患者可见范围。分类清单缺失或冲突时登记决策点，
等待作者确认并写回对应 truth；界面不得自行补造分类，也不能通过隐藏标签掩盖错误归属。
