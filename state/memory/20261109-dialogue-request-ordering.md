# 多轮问答保持历史角色与本轮输入边界

## 模式

多轮模型请求应按“系统约束 → 已验证的历史 user/assistant 消息 → 本轮 user 输入”构造。
不要把历史重新作为本轮 JSON 尾部的 `recentConversation`，否则旧问题可能被当成本轮问题
回答，或把先前的评估意图错误套用到当前科普插问。知识与规则结果可以作为本轮受控
上下文，不能因此提升历史回答为规则或患者确认事实。

## 验证

- 检查实际请求体，而不只检查系统提示词文本。
- 同时断言历史角色/顺序、当前 user 消息位于最后、当前载荷不重复尾置历史。
- 用真实连续输入覆盖普通问题、指代追问、显式开始评估、中途解释题意、恢复原题。
- 对同源入口一起检查：问卷前科普与判定后追问都应遵守相同消息边界。
- 科普插问不得写入患者事实；待答节点的实时响应、持久化与刷新恢复必须一致。
