# 模板对齐必须核对完整生成清单

## 触发条件

已有项目声称采用某个初始化技能或模板，但只检查了少数核心文档，用户继续指出还有其他
需要创建和修改的文件。

## 做法

- 先完整读取技能及其初始化脚本，以脚本实际生成的文件和目录作为清单，不凭文档摘要猜。
- 在隔离临时目录用项目名称、作品区和系统码生成一份基线，再逐项核对目标项目的存在性。
- 把差异分为三类：模板结构已填入项目事实、模板要求但缺失、项目已明确登记的本地特例。
- 对已演化项目保留事实、隐私、命名、医学和 Git 特例，只移植模板机制，不用通用占位覆盖
  已确认事实。
- 把核心缺失项加入结构检查，防止本轮补齐后下次再次静默缺失；私密目录只放行可跟踪的
  边界说明，不放行内部内容。
- 最后执行清单校验、目录检查、双入口一致性和技能要求的空会话冒烟。

## 边界

“与模板一致”不等于逐字相同。模板提供职责、结构和默认机制；项目事实必须来自项目证据，
明确登记的本地特例继续有效。涉及删除、迁移历史材料或改变权威来源时仍需单独确认。
