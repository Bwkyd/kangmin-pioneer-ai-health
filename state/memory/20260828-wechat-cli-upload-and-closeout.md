# 微信小程序上传分层验收与 CLI 服务端口收尾

微信小程序上传必须分三层记录：工程编译与静态检查、微信上传接口 `success`、真机/体验版/审核/客户验收。
`success: true` 只能证明第二层，不能扩大为正式发布或客户验收。

AppID 只注入临时上传副本，仓库 `project.config.json` 保持空值，AppSecret 永不进入小程序工程或仓库；
上传前仍要确认开发者权限和合法域名边界。

使用微信开发者工具 CLI 时先回读 `cli islogin`，再核对请求是否真正包含工程、AppID、版本、描述和二维码输出
参数；不要把命令退出、二维码文件存在或 `--info-output` 存在等同于上传成功。若工具版本漏传参数，记录
具体版本与本机 service endpoint 的临时办法，或升级/修复工具，不污染业务代码。

若官方 `preview`/`upload` 与按当前工具源码确认、显式传入工程和 AppID 的 `/v2` 请求都返回
`41002 appid missing`，且登录态、临时工程身份、路径、版本和描述均已回读，应把它归为微信账号/AppID
绑定或平台前置条件阻塞。保留客户端的 fail-closed 降级，不为绕过上传错误修改业务代码，也不把退出码、
截图或信息文件当成上传成功。

同一任务只维护一个临时预览副本和一个已打开的开发者工具窗口：首次打开后，后续编译、上传和二维码生成
均复用它；除非窗口不存在或作者明确要求，不再执行 `cli open` 或并排打开旧副本。版本更新时优先刷新该
临时副本，完成后再关闭或按作者指示保留。

仓库工程需要保持空 AppID 时，同步到已注入身份的临时项目必须显式排除 `project.config.json` 和
`project.private.config.json`；同步后先回读临时 AppID，再执行预览或上传。不要用全目录覆盖把仓库空配置
带回临时项目，也不要把临时 AppID 反向同步进仓库。

开启本机 CLI 服务端口必须有作者明确授权；上传后退出工具、恢复所有相关配置档为关闭/空值，并用 `lsof`
实测无监听。

本记忆只保留可复用的上传与本机端口安全边界；单次上传的版本、包大小、工具缺陷和执行证据记录在
`docs/changes/ops/001_native-miniprogram-cli-upload.md`，不在记忆中复制。
