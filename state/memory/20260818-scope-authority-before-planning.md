# 报价范围先于产品补全

功能分组和开发计划必须先区分三类内容：

1. 报价 truth 明确写明的交付功能；
2. 为实现已承诺功能不可缺少的技术能力；
3. 根据代码缺口、体验连贯性或产品判断提出的候选改进。

第三类即使合理、重要或能形成更完整闭环，也不能自动升级为报价内范围、P0 任务或开发授权。
分别写入报价的两个功能，也不能未经确认就推导出两者之间的联动、历史、入口或统计能力。

正式建立开发计划前必须：

- 直接读取 `vault/truth/抗敏先锋AI小程序报价表.md`，定位到对应栏目或条目；
- 把原文范围、必要技术实现和候选增项分别列出；
- 查阅 `docs/product/` 了解客户决策过程，但涉及范围的变化须经作者确认并写回报价 truth 后才生效；
- 只有现行报价 truth 明确覆盖的内容才能标记为“已确认，待开发”。

如果缺少读取 truth 的工具或权限，只能记录“待原件核验”，不得依赖历史摘要、现有代码或体验
推断生成正式实施计划。发现范围依据错误时立即停止相关开发并标记受影响材料；移动、撤回或删除
材料仍需遵守授权边界，已经进入正式编号索引的编号不得复用。
