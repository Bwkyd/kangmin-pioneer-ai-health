# 管理后台按运营任务组织而非暴露基础设施

管理后台的一级入口应对应运营人员能够说清楚的任务，例如新增文章、上传视频和添加 AI 知识；
不要把素材存储、索引或引用关系等内部对象直接提升为一级导航。底层能力可以继续统一实现，
但应在具体任务内自动调用，只有复用、替换、引用检查或清理时才进入二级管理界面。

## 做法

- 先问“运营人员要完成什么”，再设计导航和主按钮；技术实体只在确实需要独立维护时暴露。
- 文件上传、进度、失败原因和重试留在文章、视频或知识的当前流程，避免跨页面寻找下一步。
- 对含多个状态的知识流程，按上传、解析/索引、测试、启用显示唯一主要下一步；状态生效必须
  明确，失败时不得静默进入患者真实路径。
- 列表增长后使用有界分页；分页基于当前筛选结果，并保留目录、搜索、状态和仍有效的当前页。
  数据变化使页码失效时回到最近有效页，不能让用户落在空白页或无提示跳回首页。
- 可见术语调整覆盖侧栏、面包屑、标题、工作台入口、空状态、提示和无障碍名称；内部稳定标识、
  truth 与历史档案不为表面统一而机械替换。

## 边界

隐藏一级入口不等于删除底层能力或数据。重组前必须核对已有引用、删除保护、权限、对象存储和
患者可见链路，并用原数据验证升级前后引用不变。分页大小、具体术语和入口层级仍由项目当前
书面决策确定，本模式只约束任务导向、状态连续性和安全回归。
