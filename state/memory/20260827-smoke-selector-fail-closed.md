# 快速冒烟必须证明目标实际执行

测试命令退出 0 只说明测试运行器没有报告失败，不代表目标行为真的被执行。Node 多文件
`--test-name-pattern` 在零命中时可能输出文件级 `ok`，若直接把多文件组合命令当作冒烟入口，
改名、路径漂移或筛选失效会形成假绿。

## 做法

1. 为每个行为登记唯一的测试文件和逐字测试名；每个目标单独启动测试进程，构建后再运行。
2. 解析 TAP 中实际执行的非跳过测试，要求目标名唯一且完整匹配；文件级 `ok`、零命中、
   部分命中、测试进程失败或信号退出均返回非 0。
3. 至少做两类有界反证：故意改错目标名，确认选择器拦截空跑；故意改坏目标断言，确认
   子进程失败传播到总入口。恢复后再跑一次正向命令，证明实验没有污染产物。
4. 快速入口只编排既有高信号断言，不复制 fixture；PostgreSQL、S3/MinIO 等外部适配器
   的本地跳过必须单独标注，并由 CI 提供真实证据。

## 停止条件

无法从输出证明每个目标实际执行、需要复制大型 fixture、或入口开始改变业务实现时，停止
扩展快速命令，回到测试账本重新划分行为。
