# 演化基线只能收紧不能复用旧额度

结构体检的观测与门禁分工不同：观测保留全景，门禁只阻止退化。不能为了让门禁首日全绿而把存量
异常伪装成永久上限，也不能只设一个绝对阈值，导致已经改善的目录或文件重新长回旧额度。

## 基线纪律

1. 新目录和新代码文件直接服从统一上限；存量例外逐路径登记基线 commit、责任人、原因和到期日。
2. 存量值只能持平或下降；一旦下降，配置必须同步收紧或删除例外，旧额度不能继续保留。
3. 到期按真实仓库重新审计，不自动延期；配置缺失、损坏或过期均失败关闭。
4. 门禁以 Git 索引代表提交候选，未跟踪文件不参与；验收必须先 `git add` 一个故意违规样本，确认它
   真能失败，再撤销探针。
5. 文件长度按逻辑行计算，非空文件末尾没有换行时仍要补计最后一行；阈值测试同时覆盖 600 行、
   601 行以及 601 行无末尾换行的变式。
6. 独立 CLI、项目总检和 CI 共用唯一判定实现；不得复制成口径不同的多个脚本。

代理指标只用于观察方向。测试带来的必要夹具可能提高字面重复率，不能为了压低数字删掉边界证据；
应同时看用例密度、导航成本、尾部长文件和真实变更理解范围。
