# 智能体调研先定角色：患者科普问答型，不是写码型

## 适用场景

为 kangmin 的智能体能力做调研、派活或借鉴外部 agent 框架（Claude Code 类、opencode、
pi 等）之前。

## 强制做法

1. 先定产品标杆与角色：本项目智能体是面向患者的科普问答型（客户口径：通用科普 +
   引导问卷 + 问卷后追问），标杆对照物是小荷医生（定位+视频+追问）；写码/执行型
   agent 框架不能直接套到患者问答场景。
2. 借鉴写码型框架时只取其最小循环结构（模型↔工具↔结果循环），不照搬其工具集与
   代码工程习惯；太重的内容只借架构、不借实现。
3. 泄露或未授权的源码（如 Claude Code 泄露源）只可了解概念，不抄实现、不克隆入库；
   克隆第三方仓先进 `resources/clones/`（不进 git），先查 LICENSE。

## 边界

角色定位不改变权威顺序：证型判定、诊疗框架和医学内容仍由 `vault/truth/` 与后台知识库
唯一管控，AI 不自行推理证型、不脱离给定穴位/疗法新增方案。
