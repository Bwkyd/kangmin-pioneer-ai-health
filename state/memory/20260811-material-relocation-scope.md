# 资料移动必须锁定清单与动作语义

## 适用场景

用户要求整理、移动或归档权威资料时，尤其是 `vault/` 中不会被 Git 保护的私密文件。

## 强制做法

1. 动手前列出源文件、目标路径和动作；“移动”不得擅自扩大为删除目录、制造副本、改写
   正文或归档其他文件。
2. 用户只指定某类文件时，不把同目录原件、转换稿或 README 自动视为同一处理范围。
3. 移动后同时列出源目录和目标目录清单；可计算哈希的原件必须核对哈希。
4. 权威位置和冲突顺序由用户明确决定并写入仓库入口；Agent 不以自建分层替代用户的
   目录语义。
5. Git 忽略区的删除通常无法用 Git 恢复；没有明确“删除”授权时只做可逆移动。

## 边界

目录整理只改变位置和索引，不自动授权修改业务代码、历史文档结论或资料正文。发现现有
实现引用已撤销资料时，先停止开发并形成受影响清单，再单独获得回退授权。
