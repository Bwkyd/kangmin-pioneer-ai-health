# 内容关联必须全量可达并在消费时复核

## 规则

后台内容已经发布，不等于所有患者入口都能找到它。凡是由一个实体关联另一个内容实体的页面，
必须保证候选集合全量可达，并在真正消费详情时重新确认当前可见状态。

- 列表首屏可以分页，但关联查找不能静默只看首屏，也不能设置会在更大数据量下重新漏配的固定总量上限。
- 分页聚合应按稳定 ID 去重，并在短页、空页或没有新增 ID 时终止，防止异常重复页造成无限循环。
- 列表读取与点击详情之间可能发生下架；详情失败后应移除失效入口并恢复明确的安全提示。
- 人群、类型或方法相近时不能只靠宽松包含匹配；当前约定必须有正反例回归，长期应优先使用显式稳定标识。

## 为什么

“后台看得到、患者端看不到”通常不是上传失败，而是读取范围、关联键或状态时序不一致。只测少量
内容和成功点击会掩盖首屏边界、下架竞态和近似标题误配，最终在内容增长后复发。

## 验证方式

关键关联至少覆盖：目标位于第二页及更后位置、最后一页恰好满页、异常重复页可终止、发布后下架、
重新发布恢复、同名或近似标题不跨类型/人群误配，以及原有列表和详情入口不回归。断言应落到患者
可见按钮、详情内容与失败后的界面状态，不能只检查后台记录或 HTTP 成功。
