# kangmin 演化记录（给人类）

> 本文件回答三问：**变了什么、为什么变、对你意味着什么**。每个里程碑一条，倒序追加。
> 想看更细：AI 工作流水见 `state/board.md`，完整历史见 git log。规则见 `meta/kangmin_directory-protocol.md` 第二节。


## 2026-08-17 · 原生小程序非智能体薄壳形成可编译候选

**变了什么**：新增原生微信小程序首页、症状记录、月历趋势、文章/视频与四入口底栏，复用
现有患者命令协议；视觉已按患者 Web 的品牌横幅、首页模块、卡片和五格导航原样转换为微信
组件，不另建新风格。微信身份未配置时私有能力安全关闭，问助手只保留边界说明。

**为什么变**：作者决定把需要客户拍板的智能体路线留到最后，先完成报价中低客户依赖、可由
开发侧独立验证的原生患者端基础。

**对你意味着什么**：后续不必从小程序页面骨架起步；实现已提交为 `bb60564` 并进入合并流程，
但仍未上传或部署；
真实 AppID、合法域名、微信登录、真机与客户验收仍需外部资源到位后完成。


## 2026-08-15 · 诊一诊智能体进入客户试用反馈阶段

**变了什么**：Web 试用环境已跑通确定性问卷判定、患者级评估继承、千问受约束转译与连续
追问、已审核知识引用、刷新恢复和安全分片展示；关闭千问默认推理后，公网真实追问由此前
18–26 秒降至约 2.28 秒，纯寒暄约 0.25 秒。

**为什么变**：客户需要的不是固定模板，而是问卷判定后的动态解释和可持续追问；同时必须
保证模型不能改变规则结果或补造医学细节，等待速度也需达到可实际试用的水平。

**对你意味着什么**：当前 Web 小闭环可以交给客户体验，项目转入“待客户反馈”；后续只根据
实际反馈收敛，不把作者侧测试通过冒充客户验收，也不提前扩大到整本手册、正式生产或原生小程序。


## 2026-08-14 · 六组骨架按初始化方法归位

**变了什么**：项目以 `aias-meta-init` 为基线补齐插件清单、确定性检查、动态评审和
notes 边界说明；进一步把 Codex 定为主要 Agent，以 `AGENTS.md` 为主规约，补齐 `.codex`
项目设置和 `.agents/skills` 官方技能发现入口；README、兼容规约、技能与规格索引同步归位。

**为什么变**：原有 `.42cog/` 已完成项目化，但脚本与扩展骨架不全，多个入口也没有完整
承接初始化方法，换会话后仍需靠隐含上下文补足工作方式。

**对你意味着什么**：从 README 看项目，Codex 从 AGENTS 开工、Claude 从同步兼容副本开工，
从 board 接续；运行
`python3 scripts/check-manifests.py` 与 `python3 scripts/structure-lint.py .` 即可机械确认骨架。
