# kangmin · 意向书

> 意向即行动。这一份文件决定这个系统会长成什么样。
> **只有一处必须你亲自过目：收敛方向。其余是草稿，看不顺眼再动。**
> **它现在一定是粗的。跑完 `-research` 会回来改——四步是循环，不是直线。**

## 收敛方向（唯一）

让过敏性鼻炎患者在不越过医学边界的前提下，获得**有依据、听得懂、能执行、可持续**的
鼻健康管理：从通用科普与问卷引导，到规则判定后的调理建议与追问，再到症状记录与趋势
回看。

怎么算数：每件产出必须直接闭合或明确支撑以下三个闭环之一；量不出关联的产出不做。

- 可信内容：运营维护文章、视频与知识，患者能够查看，智能体能够检索；回答可追溯，
  未检索到依据时明确说明依据不足。
- 安全调理：通用科普与问卷引导 → truth 规则判定 → 通俗调理建议与已核验视频引用 →
  判定后追问；模型不参与证型、分期和诊疗框架判定，越界医学内容零出现。
- 持续管理：患者填写症状量表 → 按日期保存 → 日历与趋势正确回显，让变化可回看。

## 真难题

**医学刚性边界内仍然好用的生成式对话**：让大模型只依据检索材料和规则引擎给出的
诊疗参数，把医学条目转成普通患者听得懂的话并支持多轮追问，同时不编造穴位、疗法、
次数、时长、力度或其他医学细节。

- 删除生成与追问后，固定模板无法提供客户已确认的动态生成和持续追问体验。
- 一句提示语或一个单点工具不能稳定解决；实验已复现模型自创操作数值，需要检索、
  白名单、输出校验和安全降级共同约束。
- 该问题会在患者式输入与多轮交互中反复出现，必须持续用患者式问法验证自然度与边界。

## 不做什么

| 不做 | 为什么不做 |
|---|---|
| 不做过敏性鼻炎以外的通用医疗平台 | 系统只承接 truth 与报价确认的鼻健康管理能力，其他疾病问题不自动扩入范围 |
| 不做 AI 自主诊断 | 证型、分期和诊疗框架由 truth 与规则引擎判定，模型只做科普、转译和受约束答疑 |
| 不在问卷前生成个人调理建议 | 问卷前只提供过敏性鼻炎通用科普与问卷引导，完成规则判定后才生成调理建议并开放相关追问 |
| 不生成无依据的医学细节 | 名单外穴位、疗法、禁忌、次数、时长、力度及未确认结论一律不产出，无法确认时安全降级 |
| 不把视频生成当成交付能力 | 系统只引用已核验的视频资料，不承诺模型现场生成视频 |
| 不替代专业医疗诊断或承诺疗效 | 系统只提供过敏性鼻炎科普和居家辅助调理建议，不把输出称为诊断或最终医疗方案 |
| 不自动扩张交付范围 | 报价外组件、成本或功能只作为候选，范围变更须由作者确认并写回 truth |

## 真相源与权重

冲突时先按资料职责裁决，不把所有来源排成可以跨职责覆盖的单一序列：

1. `vault/truth/抗敏先锋AI小程序报价表.md` 裁决功能范围、所属端、价格和工期；
   `vault/truth/` 中对应专项文件分别裁决题面、证型与期别、调理方法和视频内容。
2. 客户原始材料与沟通记录用于追溯意图；只有经作者确认并写回对应 truth 后，才成为开发与
   验收依据。
3. `docs/`、`state/`、代码和测试只记录决策、状态与实现证据，不能反向覆盖 truth；同一职责
   仍冲突或缺失时停止推断，等待作者确认。

## 作品区

- 目录：`src/`
- 系统实际产出什么：面向患者的抗敏先锋鼻健康小程序，以及供运营维护文章、视频和智能体
  知识资料的管理后台。
- **怎么算合格（验证闭环）**：报价内患者端与管理端功能按 truth 完成；规则引擎负责确定性
  判定，大模型只做有依据的通俗表达和受约束追问；症状记录、日历趋势、文章、视频与知识库
  从后台维护到患者使用或智能体检索形成可验证闭环，越界医学内容零出现。
