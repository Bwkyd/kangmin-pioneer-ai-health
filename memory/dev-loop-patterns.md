# 可复用开发模式

只记录经过证据复核、能够跨任务复用的开发模式。当前状态、一次性数字和临时待办不写入本文件。

## 临床智能体的规则与模型分权

- 适用场景：含高风险筛查、分级或证型判断的健康智能体。
- 模式：按“安全门禁 → 适用资格 → 分级 → 分类”执行确定性规则；模型仅提取候选或解释已确定结果，服务端必须重新计算，不能信任前端或模型提交的结论。
- 边界：所有健康字段使用显式三态值，未知不等于否；高风险、冲突、无命中和信息不足均停止猜测；没有经审核知识与方案时返回固定降级。
- 候选确认：自由文本提取不能直接改写结构化答案；用户需逐项采用或忽略，并保留采用前的原值，使“忽略、清空描述、重新提取”能恢复而不是残留候选值。模型对安全字段只能提出升级风险的 `yes` 候选，不能用 `no` 降低风险。
- 展示顺序：规则结果先展示，模型解释异步补充；解释失败不能撤销、覆盖或延迟规则结果。
- 证据：`tests/unit/rules/agent-rules.test.mjs` 穷举严重度与证型组合，`tests/unit/api/agent-api.test.mjs` 验证模型越权、失败和不调用门禁。

## MVP 能力声明与真实链路同步检查

- 适用场景：从静态演示转为可运行 MVP。
- 模式：除了主页面，还要同步检查页面元数据、分享摘要、空状态和结果页；未接入的知识库、持久化、趋势或方案必须明确为未接入，不能保留演示性能力声明。
- 验证：生产构建后启动完整服务，在随机本地端口同时请求页面与真实 API，至少覆盖正常、冲突、高风险和外部模型降级路径。
- 证据：`tests/rendered-html.test.mjs` 与 `tests/e2e/agent-http.e2e.test.mjs`。

## 三态问诊中的未回答与明确不确定

- 适用场景：服务端规则要求完整三态载荷，但前端需要按规则动态补问。
- 模式：传给规则引擎时把未回答字段规范化为 `unknown`；会话导航仍保留 `undefined` 与显式 `"unknown"` 的区别，只追问服务端 `nextQuestions` 中尚未回答的字段。
- 收益：未知不会被误当作否，用户明确选择“不确定”后也不会被同一问题循环追问；前端只负责导航，不复制临床规则。
- 验证：用真实 `evaluateAssessment` 组合测试覆盖安全顺序、高危短路、转诊、全部 unknown 和提前分类。
- 证据：`lib/agent/conversation.ts` 与 `tests/unit/rules/conversation.test.mjs`。
